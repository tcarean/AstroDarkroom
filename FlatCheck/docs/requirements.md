# Requirements

The source of truth for behaviour. Code follows this file, not the reverse. A behaviour change is
first an edit here (status `draft`), then a test, then code (status `implemented`).

Rules for entries:

- IDs are `R-NNN`, assigned once, never reused. A dropped requirement keeps its ID with status
  `dropped`. Gaps in the numbering are deliberate: each block of ten is one area.
- Status is one of `draft`, `accepted`, `implemented`, `dropped`. `implemented` means a test named
  `R###_...` exists in `FlatCheck.Tests` or `FlatCheck.Wpf.Tests` (`RepoInvariantTests` checks it
  both ways). `accepted` means the behaviour is agreed and in the code, and its tests do not carry
  the ID yet; that is the state of most rows since the migration of 2026-09-25 (ADR 0001), and a
  row moves to `implemented` when its area is next touched and its tests are renamed.
- Describe observable behaviour, with one concrete example that includes numbers. No adjectives.
- Error behaviour and the exit code are requirements too.
- Thresholds are quoted by their `Th` name and their value on 2026-09-25; the constant in
  `Thresholds.cs` is the value, this file is the meaning.

The explanations behind each row (why this way, what was measured) are in `docs/design/` and
`docs/decisions/`; the user documentation of the same behaviour, in English, is `README.md`.

## Console contract

| ID | Status | Requirement |
| --- | --- | --- |
| R-001 | implemented | Every run prints `flatcheck <version>` as its first line and `Copyright (C) 2026 Tudor Carean` as its second, in every mode, for `--help`, and on a failed run. The version is the `<Version>` of `Directory.Build.props`; there is no `--version` flag. A machine-readable output, if one is ever added, carries the same two strings as its first two fields, in this order, before any result (example: `"flatcheck": "2.2.0"`, `"copyright": "Copyright (C) 2026 Tudor Carean"`), and prints no banner lines; none exists today (ADR 0042). The banner is written before the options are parsed, so no option can suppress or move it; that machine-readable output is the only exception. |
| R-002 | implemented | The exit code follows the verdict: `0` for `OK` / `PERFECT` / `BUN`, `2` for `SUSPECT` / `ACCEPTABIL` / `NEDETERMINAT` and `--expo`'s two "acceptabil, dar" bands, `3` for `PROBLEMA` / `REFA`, `1` for an error (missing file, bad argument, invalid FITS, failed fit, `--expo` on a file that is not a raw flat, `--light` on a field too wide). Severity is monotonic, so any non-zero code means "not clean". |
| R-003 | implemented | Modes are mutually exclusive and dispatched in the order `--lenses`, `--synthetic`, `--against`, `--smooth`, `--histeq`, `--expo`, `--light`, structure (default); the first match wins. A flag is accepted before or after the file path with the same result. Example: `flat.fit --histeq --expo` runs `--histeq`. |
| R-004 | accepted | Input is a FITS file (`.fit` / `.fits` / `.fts`; BITPIX 8, 16, 32, -32, -64; a colour cube is averaged over its planes) or a camera raw dispatched by extension (`.nef`, `.cr2`, `.cr3`, `.arw`, `.dng`, `.raf`, `.pef`), read undebayered through libraw with the exact black and white levels. A raw has no FITS header (an empty dictionary). When the libraw assembly or its native DLLs are missing, a FITS run is unaffected and a raw run exits `1` with a message naming what is missing. Any other extension is parsed as FITS and fails as one. |
| R-005 | implemented | `--help`, `-h` or no arguments prints the usage, the GPLv3 warranty disclaimer (`RunReport.WarrantyLines`) and a pointer to `LICENSE`, and exits `0`. An unknown option, a missing value, two input files or a nonsensical value (`--sat` at or below `--black`, an empty `--pattern`, a negative `--fov`) exits `1` with a message naming the argument. |
| R-006 | implemented | The residual map is written as a PNG to `-o <path>`, also spelled `--out <path>` (default `flatcheck.png`); a second map goes beside it with the suffix `-after` (`--smooth`), the same in both languages (R-103; `-dupa` until 2026-10-25; `--ratio` wrote a `-world` map until its removal on 2026-10-26, ADR 0067). Every file on disk is on the automatic colour scale (1st to 99th percentile, 10 % padding, white at 1.0). |
| R-007 | implemented | The console formats and parses numbers with `.` as the decimal separator whatever the Windows culture (`<InvariantGlobalization>` in `flatcheck.runtimeconfig.json`: `0.24`, never `0,24` on a Romanian Windows). `FlatCheck.Tests` runs under the same switch, so the golden files and every report test compare against the console's formatting, not the test machine's culture (ADR 0043). |
| R-008 | implemented | The two reads of a file dispatched to the FITS reader, the full load (`ImageLoader.Load`) and the metadata-only read (`ImageLoader.LoadInfo`: the lens identification, the window's Sintetic prefill, the reason card of its Structure tab), refuse the same files with the same `InvalidDataException` and message: `FITS: fisierul nu incepe cu SIMPLE.` for a file that does not begin with the `SIMPLE` card (an empty file, one shorter than the 8 bytes of a keyword, a whole 2880-byte block whose first card is `NAXIS`), and `FITS: header incomplet.` for a header that begins with `SIMPLE` but ends before `END` (100 bytes, or one block without `END`). The metadata read never answers with an empty header. Example: a 100-byte text file named `pp_flat_stacked.fit` as a session's master makes the Sintetic tab say `preumplerea a esuat: FITS: fisierul nu incepe cu SIMPLE.` instead of leaving every field empty without a word, and `flatcheck photo.jpg` exits `1` with that message instead of `header incomplet` (ADR 0057). |
| R-009 | implemented | The full load of a FITS (`FitsReader.Load`, so `ImageLoader.Load` and every mode) refuses a file whose data area is shorter than its header declares (the product of the `NAXISn` times `|BITPIX| / 8`; a copy cut mid-transfer) with `InvalidDataException` and `FITS: data cut short: the header announces <n> bytes of pixels, the file holds only <m>.` (`FITS: date trunchiate: octeti de pixeli anuntati de header: <n>, in fisier doar <m>.` in Romanian), `<n>` the declared bytes and `<m>` the bytes after that header, instead of an `IndexOutOfRangeException` out of the sample loop. The check runs for every HDU before a sample is read, so a cut HDU without a 2D image is refused too (a 1-D HDU of 200 declared bytes cut after 100), and it counts the data alone, so a last HDU missing only its padding to 2880 bytes is read. The metadata read (`ImageLoader.LoadInfo`) does not check the data area: such a file's header is intact, so the Sintetic prefill still answers on it; this is the one refusal the two reads of R-008 do not share. Example: a header for a 4 x 4 16-bit image followed by 8 data bytes is refused with `32 bytes of pixels, the file holds only 8`, exit `1`; the same header followed by 32 data bytes and no padding loads. |

## Mode 1: structure (default)

| ID | Status | Requirement |
| --- | --- | --- |
| R-010 | accepted | The frame is prepared by a 2x2 block mean (so an undebayered CFA master keeps its radial profile) and a further block mean by `k = max(1, int(longSide / 1200))`. Example: 6000x4000 becomes 1500x1000, not 1200x800. Partial blocks are dropped. |
| R-011 | implemented | Five deviation tests are computed on the prepared raster, each a percentage: corner spread (the four 5 % corner-box medians against each other), azimuthal asymmetry (max over 10 rings x 12 sectors inside the inscribed circle of `(max - min) / median`), residual after the radial model (`p95 - p5` of ~40-wide tile means of `img / model`, whole frame), tilt (`2 sinh(|b| + |c|) x 100` from a paraboloid fit on `log I`), worst tile (`max |tile - 1|`, whole frame). The verdict is the worst of the five. Example: a 12 % linear gradient on a 3:2 frame reads tilt 12.0, corners 11.5, residual 10.4, azimuthal 7.3, worst tile 6.0. |
| R-012 | implemented | The five tests share one scale: `< Th.ResidPerfect` (2 %) `PERFECT`, `< Th.ResidUsable` (10 %) `BUN`, `< Th.ResidCheck` (20 %) `ACCEPTABIL`, else `REFA`; boundaries are strict `<`; `NaN` reads `REFA`. The report prints the scale under a heading that names the number of tests, and marks the residual as the metric that matters most. |
| R-013 | implemented | Informative rows carry no verdict: the vignetting depth in stops (`log2(centre / corner mean)`), the illumination-centre offset as a percentage of the half-diagonal (`nedeterminat` when the fitted vertex is singular or outside the frame), under it a note that the offset is a gradient/curvature ratio, not scale-invariant, growing on a lens with almost no vignetting until the peak leaves the frame and the row reads `nedeterminat` (never that it falls back toward 0, which it did before ADR 0014), and the deepest compact spot after the large-scale structure is subtracted, with its sign named in words (`mai intunecat` / `mai luminos`) and its position. A spot at or beyond `Th.LocalSpotWarn` (2 %) adds a warning that states that threshold; it never changes the verdict. |
| R-014 | accepted | The radial model is built around the sensor centre `(w/2, h/2)`, never around the fitted illumination peak, from the mean of the raster and its 180° rotation, with the even 2θ + 4θ correction on the rings from 0.75 of the inscribed radius outward (one relative amplitude per r²). On a smooth field with a gradient, a saddle or a four-fold term the residual carries no rings of the model's making: the largest ring-to-ring step of the residual's ring mean stays under 0.5 %. |
| R-015 | accepted | The residual map is a diverging blue-white-red image of `img / model` with white pinned at 1.0. The window offers the same map on fixed caps of ±2, ±10 and ±20 % (`Th.Resid*`), default ±10, with a legend stating the displayed ends; the chips change no file and no number. |
| R-016 | implemented | With `--raw <flat.NEF>` or `--lens <text>`, the master's vignetting depth is compared with the nearest profile (nearest focal, then nearest f-stop in stops, then farthest distance) of every candidate lens, each profile built as a raster at analysis size and measured with the same corner operator as the master. The difference in stops becomes an error `2^|D| - 1` on the residual scale (0.03 / 0.14 / 0.26 stops). The depth verdict is the nearest profile's; the run's verdict is the worse of shape and depth and the exit code follows it. Under the depth scale the report also prints what `--light`'s 2 / 5 % scale would say of the same corner error, and the reference's own spread `Th.ProfileDatabaseSpreadStops` (0.2 stops). Without `--raw` or `--lens` the output is byte-identical to the plain run. Example: the fixture master at k = 0.6 against the fixture profiles reads `BUN` on shape, `REFA` on depth, exit `3`. |
| R-017 | implemented | When the comparison cannot be made it votes nothing and says why: no profiles on the machine, no raw and no lens text, a raw that says nothing about the lens (R-106), an ID that matches nothing, no focal length, no f-stop (a Siril FITS carries none), or only lensfun profiles without a camera crop. The five-test verdict stands. |
| R-106 | implemented | A raw that was read but says nothing about the lens - no lens ID, no lens name and no focal range, what a camera on a telescope or on a lens without contacts writes - is named as such, never as a missing raw. The console's gap reads `IMG_7290.CR2 says nothing about the lens (no lens ID, no lens name, no focal range): a telescope, or a lens without contacts. Give --lens <text>`, with `--focal <mm>` and `--fstop <f>` added for whichever of the two is unknown too; the Structure tab's card says the same; the Synthetic tab leaves the aperture empty and its prefill note carries the same sentence. A manual lens on a Nikon (ID 74 with the range from the menu) is not this case. Example: a Canon EOS 40D session whose CR2 files carry focal length 0, aperture 0 and lens ID 0 (measured 2026-10-26) no longer reads `no raw beside the master (in flats/)` with 17 raws in `flats/`. |
| R-018 | implemented | Candidate lenses come from what the raw says of its lens, two keys: the lens ID (R-108) matched against the Adobe profiles' `LensID` and `AlternateLensIDs`, and the lens's name as the camera wrote it (EXIF `LensModel`, `LoadedFrame.LensName`) matched letter for letter, case and punctuation aside and the lens's maker allowed in front, against the Adobe `Lens` and `LensPrettyName` and the lensfun names and aliases; the name's matches are the candidates when any of them survives the range (an ID is shared: Canon's 198 is the EF 50mm f/1.4 USM and three Zeiss ZE lenses, every Canon RF lens is 61182), the ID's otherwise. They are narrowed by the raw's focal range and aperture (`LensSpec.Parse` on the lens name; 1 mm or 5 % on a focal, a quarter stop on the aperture). When the ID decided, the lensfun lenses of the same makers whose name does not contradict the range join, the range being the raw's or, when the raw gives none, the one every matched name agrees on, and so do the lensfun lenses whose name is letter for letter an Adobe hit's name or alias. A lens ID that matches no profile (a manual lens, ID 74) with a full range yields the lenses of the mount whose name states exactly that range. Examples: ID 139 on a Nikon raw shot at 11-20 mm f/2.8 yields the two Tokina 11-20 Adobe files and the two lensfun entries, not the Nikkor 18-200; a Canon EOS 7D Mark II raw with ID 198 and the name `EF50mm f/1.4 USM` yields the Adobe `Canon EF 50mm f/1.4 USM` file and the lensfun entry of the same name, not the Zeiss ZE files that share ID 198; a Sony ILCE-7M3 raw with the name `FE 16-35mm F2.8 GM` and ID 32831, which no profile carries, yields the Adobe and the lensfun `FE 16-35mm F2.8 GM` and not the A-mount `16-35mm F2.8 ZA SSM` of the same range; a Pentax K-70 raw with ID 2263, no name and no range yields the Adobe `smc PENTAX-DA 18-135mm F3.5-5.6 ED AL[IF] DC WR` and the lensfun entry of the same name. |

| ID | Status | Requirement |
| --- | --- | --- |
| R-020 | dropped | Dropped 2026-10-26 (ADR 0067): the mode is removed from the console and the window; `--ratio` is an unknown option. ## Mode 3: end-to-end on a light (`--light`)

| ID | Status | Requirement |
| --- | --- | --- |
| R-030 | implemented | On a calibrated light (no background extraction), the 15th percentile of each tile is fitted with `a + bX + cY + dR² + eR⁴` (X, Y normalised by the half-diagonal) through 4 rounds of one-sided 2.5 σ clipping (σ = MAD x 1.4826). The figure is `radPct = -(d + e) / a x 100`: `|rad| < Th.LightRadOk` (2 %) `OK`, `< Th.LightRadBad` (5 %) `SUSPECT`, else `PROBLEMA`. The sign is the diagnosis: positive prints `Fondul CADE spre margini` (under-correction), negative `Fondul CRESTE spre margini` (over-correction, a flat that still holds an offset). |
| R-031 | implemented | Before any pixel is read the diagonal field of view is derived, most trusted source first: `--fov <deg>`, WCS `CDELT1` / `CD1_1`, `XPIXSZ` + `FOCALLEN` (+ binning), `FOCALLEN` alone (graded on the focal length against a full-frame diagonal: `>= Th.LightFocalOk` 120 mm fine, `< Th.LightFocalMin` 60 mm refused, between them marginal, no field figure printed), nothing (runs, with a note). Below `Th.LightFovOk` (20°) the run is normal, up to `Th.LightFovMax` (40°) it runs with a warning, above that it is refused with exit `1` and no figure. `--fov` states the truth and can refuse like a deduced field. |
| R-032 | implemented | A directory runs the series: every file matching `--pattern` (default `pp_light_*.fit`, `*` and `?` only, matched in-process, sorted ordinally, so `r_pp_light_*` is excluded) is analysed one at a time with a streamed table row. The verdict is given only when the frame count is `>= Th.LightSeriesMinFrames` (5), the standard error of the mean of `radPct` is `< Th.LightSeriesSemMax` (2.0 points) and, when the sky gradient spans at least `Th.LightSeriesSkySpanMin` (10 points), `|Pearson(radPct, planePct)| < Th.LightSeriesSkyCorr` (0.70); otherwise `NEDETERMINAT`, exit `2`, naming the failed condition. `NaN` fails a condition. A directory with no match exits `1`; a directory with any other mode exits `1`. |

## Mode 4: exposure of a raw flat (`--expo`)

| ID | Status | Requirement |
| --- | --- | --- |
| R-040 | implemented | The frame is split into the four Bayer positions `(y & 1) * 2 + (x & 1)`; if the ratio of the largest to the smallest position median is `> Mosaic.CfaSpreadMin` (1.15) the file is CFA and the brightest position is the limiting channel, otherwise the whole frame is one channel. The decision figure is the median of the central 20 % x 20 % window of that channel as a percentage of the white level; the global median is printed as information only. Example: on a vignetted frame the centre reads higher than the global median. |
| R-041 | implemented | The white and black levels come from the raw itself (`color.maximum`; `black + median(cblack)`), reported `sursa: libraw (exact)`. On a FITS the white is guessed from the frame maximum: `<= 1.5` gives 1.0, `<= 4300` gives 4095, `<= 17203` gives 16383, else 65535. `--sat` overrides the white and the source line; `--black` overrides the black alone, so a bare `--sat` keeps a raw's black. |
| R-042 | implemented | Before a verdict the mode refuses a file that is not a raw flat: a centre median `< 1.0` (already calibrated or normalised) or a CFA spread `< 1.02` (debayered). It explains, gives no verdict and exits `1`. |
| R-043 | implemented | Bands on the centre figure: clipping (`> Th.ExpoClip`, 0.05 % of the window at white) or `> Th.ExpoTooHigh` (80 %) `PREA SUS`; `< Th.ExpoTooLow` (30 %) `PREA JOS`; `< Th.ExpoLo` (50 %) `ACCEPTABIL, dar cam jos`; 50 to `Th.ExpoHi` (65 %) `OK`; 65 to 80 `ACCEPTABIL, dar cam sus`. With `--sky`: `Th.ExpoSkyLo` 15 to `Th.ExpoSkyHi` 50 `OK`, above `Th.ExpoSkyTooHigh` (60) or clipping too high, below 15 too low, no low shoulder. The suggested correction is `log2(target / centre)` stops with target `Th.ExpoTarget` 57 (`Th.ExpoSkyTarget` 30 with `--sky`). Clipping forces `PREA SUS` even inside the target band. |
| R-044 | implemented | The four positions are named by colour only when the file says which is which: libraw's `filters` + `cdesc` on a raw (the second green sits at index 3 on Nikon), `BAYERPAT` on a FITS shifted by `XBAYROFF` / `YBAYROFF`, and by one row when `ROWORDER = 'BOTTOM-UP'` and the height is even. Otherwise the labels stay `CFA[y,x]`. No figure depends on the names. Example: an `RGGB` frame written bottom-up at 6016x4016 is named `GBRG`. |
| R-045 | accepted | The window shows one histogram per channel (200 bins of 0.5 % on the percentage axis, clamped at both ends, whole channel and centre window each normalised to its own peak) with the band that voted shaded; a switch shows the same charts from the camera's embedded JPEG preview (the largest JPEG with a long side `<= 3000` px, else the largest decoded scaled, else a bitmap) with no bands and no verdict, and a table pairs the raw centre median with the preview's per colour. Attaching a preview changes no verdict figure. |

## Mode 5: histogram equalisation (`--histeq`)

| ID | Status | Requirement |
| --- | --- | --- |
| R-050 | implemented | The frame is rendered as Siril 1.4.4's "Histogram" display: per layer (the four Bayer positions when `Mosaic.LooksCfa`, else one), a 65536-bin histogram of the non-zero values on the layer's own `[min, max]`, `index = round(cumulative_inclusive / all_pixels x 255)` with `index[0] = 0`. The composite is R from the red position, G the mean of the two greens, B from blue (the mean of the four when the order is unknown), shrunk by `Prepare`'s `k`; the full-resolution rasters are kept for the window. The PNG goes to `-o`; exit `0` when written, `1` otherwise; no verdict, and the report prints that amplitude is gone by construction. On a CFA frame the mosaic view is the window's default. |
| R-104 | implemented | `--histeq --rainbow` and the window's "False colours" chip colour a one-layer equalised raster through Siril 1.4.4's rainbow table: `h = 300/360 - i * (300/360)/255`, `s = v = 1`, `hsv_to_rgb` with integer sectors, `round_to_BYTE`; level 0 is magenta (255,0,255), 51 blue, 102 cyan, 153 green, 204 yellow, 255 red. It applies after equalisation to the Mosaic, the channel and the mono views, never to the RGB composite; the console writes the Mosaic on a CFA frame and the channel on mono, shrunk first and coloured after, and prints the legend. `--rainbow` without `--histeq` is a parse error, exit `1`. Exit `0` when the picture was written, `1` otherwise; no verdict. |

## Mode 6: the smoothed flat (`--smooth`)

| ID | Status | Requirement |
| --- | --- | --- |
| R-060 | implemented | `flat.fit --smooth out.fit [--scale N]` writes a second master: per Bayer position (mono: the whole frame) tile medians of ~150 sensor px with partial tiles kept, a local quadratic fit at every tile over a Gaussian neighbourhood of sigma `--scale` (default `SmoothAnalyzer.DefaultScalePx`, 300 sensor px) with 3 rounds of two-sided clipping at `max(2.5 MAD, 2 % of the level)`, a bilinear blend per pixel, merged back to the original size. The output keeps the input's type (BITPIX 16 stays 16, everything else becomes -32), its cards verbatim (`BAYERPAT` included) and two `HISTORY` lines; nothing is renormalised. A raw and a colour cube are refused, the input path is refused as output; exit `0` written, `1` refused. |
| R-061 | implemented | The report prints what was removed (`Prepare(input) / Prepare(smoothed)`: p1 and p99, `p95 - p5` on tiles, the worst tile, the deepest compact spot with sign and position) and the five-test battery before and after, with no verdict; a warning when the removed component's worst tile reaches `Th.SmoothKeptWarn` (2 %). Two maps: the removed component at `-o`, the smoothed flat's own residual with the `-after` suffix. |
| R-062 | implemented | `--scale auto` proposes the scale: when the input's fine texture (`Metrics.FineTexture`, structure under ~128 sensor px with pixel noise subtracted) is `< Th.SmoothTextureMin` (0.20 %) the answer is `NIMIC DE NETEZIT`, no file, exit `2`; otherwise each rung of the three-chip ladder (half, default, double of the default scale) is tried and is acceptable when the output's texture is `< Th.SmoothTextureGone` (0.05 %) and neither the azimuthal asymmetry nor the tilt dropped by more than `Th.SmoothScaleLoss` (0.5 points); the smallest acceptable rung is proposed and used; none means `NEDETERMINAT`, no file, exit `2`. |

## Mode 7: synthetic flat (`--synthetic`, `--lenses`, `--against`)

| ID | Status | Requirement |
| --- | --- | --- |
| R-070 | implemented | `--lenses [--lens <text>] [--source adobe|lensfun] [--profiles <dir>]` lists the lenses with a vignetting profile from the Adobe LCP folders on the machine (`C:\ProgramData\Adobe\CameraRaw\LensProfiles\1.0`, `%APPDATA%\Adobe\CameraRaw\LensProfiles` and every `C:\Program Files\Adobe\<app>\Resources\LensProfiles\1.0` that exists, Lightroom Classic's and Lightroom's own copies; `--profiles` replaces them all) and from `lensfun/` beside the executable, each with its source and mount (and, for lensfun, its calibration crop); when the filtered list has at most `SyntheticReport.ListDetailsMax` (40) rows each row also carries its focals, apertures, distances and profile count. | R-071 | implemented | `ref.fit --synthetic out.fit --lens <text>` writes a float flat with 1.0 on the optical axis from the chosen lens's nearest profile, with the reference frame's geometry and cards minus the structural ones (`BAYERPAT` kept) and `HISTORY` lines naming source, lens, profile and model. The lens is chosen by text: an exact name beats partial matches; several ties list the candidates and exit `2`. Exit `0` when written. |
| R-072 | implemented | The model is the profile's polynomial `V = 1 + a1 r² + a2 r⁴ + a3 r⁶`: for Adobe, r in focal-length units through millimetres, with the frame's physical size from the camera's crop (`36 / crop` mm; the profile's `SensorFormatFactor` only when the crop is unknown) and decentring honoured; for lensfun, r = 1 at the half-diagonal of a 36x24 frame over the lens entry's crop factor, rescaled to focal units. The report prints `cerut` and `profil folosit`, a warning when the request is farther than `Th.ProfileFocalTolMm` (1 mm) or `Th.ProfileFocalTolFrac` (5 %) in focal or `Th.ProfileStopsTol` (0.5 stops) in aperture from the profile used, the format sentence (`SyntheticReport.FormatMatch`) and `extrapolare MARE` when the corner lies beyond 1.1 of the calibration corner. The written depth at four reference points is printed in stops. |
| R-073 | implemented | `A.fit --against B.fit` prepares both, normalises each to median 1 and prints three structure analyses side by side, A, B and A / B: vignetting in stops, illumination offset, local spot and the five tests. The depth difference (positive = A falls more toward the corner) becomes `2^|D| - 1` on the residual scale (0.03 / 0.14 / 0.26 stops) and is the only row with a verdict in the difference column; the run's verdict is the worse of the shape (the five tests on A / B) and the depth, and the exit code follows it. Example: the golden pair 0.30 stops apart reads `REFA`, exit `3`. |
| R-107 | implemented | The Adobe folders are searched in order: `C:\ProgramData\Adobe\CameraRaw\LensProfiles\1.0`, `%APPDATA%\Adobe\CameraRaw\LensProfiles`, then the `Resources\LensProfiles\1.0` folder of every application under `C:\Program Files\Adobe` that has one, in ordinal order of the application folder (`ProfileLocator.AdobeAppDirectories`); `Program Files (x86)` is not searched.
