# Requirements

The source of truth for behaviour. Code follows this file, not the reverse. A behaviour change is
first an edit here (status `draft`), then a test, then code (status `implemented`).

Rules for entries:

- IDs are `R-NNN`, assigned once, never reused. A dropped requirement keeps its ID with status
  `dropped`. Gaps in the numbering are deliberate: each block of ten is one area, with one
  exception from the first days, R-008 to R-012 (reading frames, the repository) numbered on
  from the console's block. A full block continues in the next free block of ten, which the
  area's heading then names: the console block R-001 to R-007 is full, so its next requirement
  takes R-080 and the heading says so.
- Status is one of `draft`, `accepted`, `implemented`, `dropped`. `implemented` means a test named
  `R###_...` exists in a test project under `tests/` (`RepoInvariantTests` checks it both ways; it
  reads the sources of the projects it cannot reference).
- Describe observable behaviour, with one concrete example that includes numbers. No adjectives.
- Error behaviour and the exit code are requirements too.

The explanations behind each row (why this way, what was measured) are in `docs/design/` and
`docs/decisions/`; the user documentation of the same behaviour, in Romanian, is `README.md`.
The nine checks of the plan (`docs/plans/2026-10-11-build-darkscheck.md`) map to the areas:
check 1 is the console contract and inventory block below; checks 2 to 8 take the blocks from
R-020; check 9 and the index take the blocks from R-050; the window is the block from R-070.

## The dark series (checks 2 to 8)

The method is the Python prototype's (`prototype/analyze_darks.py`, `supplementary.py`); every
constant is in `Thresholds.cs` (`Th`), the mechanics in `docs/design/dark-analysis.md`
(ADR 0007). Figures are in ADU above black; "ADU-eq" is ADU divided by the normalisation
factor ISO / 400 x exposure / 120 s (ADR 0004), so every threshold is the same whatever the
settings; at ISO 400 and 120 s the two are the same.

| R-020 | implemented | The darks are decoded into memory as 16-bit mosaics (the first file sets the size; a file of another size is listed with `dimensiune diferita` and left out); the scale is the file's (libraw's black and white for a raw) and, for a FITS, which carries no black level, the black is the median of the first bias' reference plane when there are biases, else of the first dark's (`negru 200 estimat din mediana cadrului 1`). For each of the four CFA positions of each frame, named from the file's colour order (`R`, `G1`, `G2`, `B`): the median, the clipped sigma (every k-th value so at most 3 million are read; the population std, then three passes dropping what lies over 5 sigma, at least 5 ADU, from the running centre), the mean, the 99.9th percentile, the counts above 10, 20, 50, 100 and 500 ADU-eq (a level is never under `Th.MinHotAdu`, 5 raw ADU, so a short or low-ISO series does not count noise as hot), the saturated (at white - 1 or above) and the dead (below black - 50 raw ADU: a dead pixel does not respond, so it does not scale), the minimum and maximum. constants are the prototype's, the mechanics in `docs/design/lights-and-index.md`.

## The index and the matching

The index is a rank statistic of the master and the matching a ratio on the pixels two sets
share (ADR 0004); the pixels compared and the label's folder are ADR 0008; the mechanics are in
`docs/design/lights-and-index.md`. Every bound is in `Thresholds.cs`.

| ID | Status | Requirement |
| --- | --- | --- |
| R-060 | implemented | The index of a master is the median excess above black, in ADU-eq, of its unsaturated pixels (under white - 1) ranked by descending excess from `Th.IndexRankLowPerMpx` (5) to `Th.IndexRankHighPerMpx` (20) per megapixel: the 0-based ranks `max(1, round(5 x Mpx))` to `max(kLo + 1, round(20 x Mpx)) - 1`, the band's median being the element at the middle rank; the line names the ranks, the megapixels and the normalisation. Example: on a 1 Mpx master with forty pixels at 1000, 990, ... 610 above black and one saturated pixel above them, the index is 880 (the 13th strongest unsaturated, ranks 5 .. 19), 220 at ISO 1600; on a 0.05 Mpx synthetic frame the band is the single strongest pixel; the Smida master reads `idx25 (25.2 ADU-eq: ... al 122-lea .. al 483-lea din 24.2 Mpx ...)`, the 2026-10-10 library 67.4. A master with no unsaturated pixel reads `idx-`. |
| R-061 | implemented | The label is the folder's name, `-idx` and the index rounded half up (66.5 reads `idx67`): the darks' parent folder when the darks sit in a `darks` subfolder (a session, or a library kept as `<name>\darks\`), the darks folder itself otherwise; a folder whose name already ends in an earlier label's tag, `-idx` and digits or the unmeasured `-idx-`, in any case (a folder the owner renamed to an earlier label), loses that one tag before the new one is appended, unless nothing would remain in front of it, so the label stays one tag long and a changed index shows as a changed number (ADR 0013); the line `eticheta` shows it and nothing is renamed (ADR 0002).
