## The fixes, one commit each (requirement, failing test, code, docs)

### CR-006 No zone width, ratio or soft-corner verdict from too few stars

- R-071: on a frame whose stars are too few (R-070, ADR 0062) every zone's width and the corner /
  centre ratio are n/a; the zones keep their counts. R-071 goes from `accepted` to `implemented`.
- `Analysis/StarAnalyzer.cs`, `Analyze`: the "too few" test moves before the regions; an
  insufficient result gets regions with their counts and `FwhmMedian = NaN`, and a NaN ratio, so
  `SoftCorners` is false and `Recommendations.Size`, Appendix D (`ReportWriter`) and the Rezolutie
  tab (`ResultTabs`) follow without a change of their own.
- Test `R071_...` in `StarAnalyzerTests`: the entry's case in small (a frame under the density
  floor with 10 stars of 3 px in the centre and 6 of 4.8 px in a corner): no zone known, ratio
  NaN, no soft corners, and no "corners" recommendation from `Recommendations`.
- Golden, meant: `mono-png8.txt` and `.en.txt`, Appendix D, one line each:
  `centru 3.09 px (6 stele)` becomes `centru n/a (6 stele)`. The whole diff is read and reported.

### CR-007 A FITS number that does not parse is not read as its default

- R-011: a real is read as FITS writes it, the `D` exponent included; a `BZERO`, `BSCALE`,
  `BITPIX`, `NAXIS` or `NAXISn` that is present and is not a number refuses the file. R-018: a WCS
  number that is present and does not parse means no WCS.
- `Input/FitsReader.cs`: one parser for a header number (`D` taken as `E`, `NumberStyles.Float`,
  finite; so "0,5", "1,024" and "(5)" no longer parse). `HDbl` and `HInt` keep their default for
  an absent keyword and throw for an unreadable one (an integer may be written as a whole real,
  "16.0"); a `TryHDbl` beside them for `Wcs.TryFrom`, which returns null when any number it reads
  is unreadable. `FitsWriter` and the header walk of `--wcs` use the same two members.
- New texts (none exists today; the value is quoted as the file holds it):
  - `FITS: the header's BZERO cannot be read as a number: '3.2768X+04'.` /
    `FITS: BZERO din header nu se poate citi ca numar: '3.2768X+04'.`
  - `FITS: the header's NAXIS1 cannot be read as a whole number: '1,024'.` /
    `FITS: NAXIS1 din header nu se poate citi ca numar intreg: '1,024'.`
- Tests `R011_...` in `FitsReaderTests` (a 16-bit FITS with `BZERO = 3.2768D+04` reads as with
  `32768`; `BSCALE = 0,5` and `NAXIS1 = 1,024` are refused) and `R018_...` in `WcsTests`
  (`CDELT1 = -1.158D-02` gives the same WCS as `E`; `CRVAL1 = 18:06:22` and `271,5922` give null).
  `FitsTestData` gets a way to write a card's value as given, if it has none.

### CR-008 At most 256 levels is 8 bits, whatever the conversion

- R-031 and R-096: the file is an 8-bit upscale when over half of the samples are `level x 257`
  (as today) or when no plane has more than `Thresholds.EightBitLevels` (256, new) distinct
  levels. R-031 goes from `accepted` to `implemented`.
- `Analysis/BitDepthAnalyzer.cs`: `IsUpscaled` takes the second clause; `Thresholds.cs` the new
  constant with its comment (the reference image uses 63 862 / 39 918 / 42 878 levels, V-001).
- `Report/Recommendations.cs`, `Warnings`: the sentence stays; its evidence today names the x 257
  form, which is false for the new case, so that case gets its own:
  - today, kept for the x 257 form: `100.0 % of the values are an 8-bit level copied into 16
    bits (the value = the level x 257; threshold 50 %); different levels used on each channel: ...`
  - new: `different levels used on each channel: 256 / 256 / 256, at most the 256 that 8 bits
    can hold, of the 65536 a 16-bit file has` /
    `niveluri diferite folosite pe fiecare canal: 256 / 256 / 256, cel mult cele 256 pe care le
    pot tine 8 biti, din cele 65536 ale unui fisier pe 16 biti`
- Tests `R031_...` in `BitDepthAnalyzerTests` (samples `n << 8`: caught, x 257 fraction near 0)
  and one on the warning's evidence. An existing test that turns red because its 16-bit fixture
  is flat (one level) is reported to the owner, not edited.

### CR-009 A second image cannot be chosen during a run

- R-110 / R-111: while a run lasts no image can be opened: both "Open image..." buttons are
  disabled, and `OpenAsync` changes nothing.
- `AstroPhotoAnalyzer.Wpf/MainWindow.xaml`: the placeholder's button gets
  `IsEnabled="{Binding IsIdle}"`, as the top bar's has. `ViewModels/MainViewModel.cs`,
  `OpenAsync`: busy, it returns a completed task with a log line, the path untouched (the guard
  `ChooseProfile` and `ClearProfile` have); its comment no longer calls CR-009 open.
- Tests: `R111_ASecondImageChosenDuringARunChangesNothing` replaces the test named in answer 1
  (open A, open B while busy: the bar reads A, A's result, B never analysed); a window test that
  the placeholder's button is bound to `IsIdle`.

### CR-010 `-o` naming a file the run reads is refused

- R-005: `-o` naming the image, the `--wcs` file or the `--icc` profile is an error before the
  analysis starts, exit 1, nothing written.
- `AstroPhotoAnalyzer/AnalyzerCli.cs`: after the files are known to exist, the full path of
  `o.Out` is compared (ignoring case, as `CurveExport.Guarded` does) with the three inputs'. For
  another spelling of the same file, the inputs are held open for reading while
  `ReportWriter.SaveFull` runs, so `AtomicFile`'s probe refuses the target and the existing
  `the report could not be written:` line tells it; the file is untouched.
- New text: `-o names a file the analysis reads (the image): m31.tif. The report would replace
  it; give the report another name.` /
  `-o numeste un fisier pe care analiza il citeste (imaginea): m31.tif. Raportul l-ar inlocui;
  da raportului alt nume.`, with `the --wcs file` / `fisierul de la --wcs` and `the --icc
  profile` / `profilul de la --icc` in the brackets.
- Tests `R005_...` in `CliTests`: the image, the WCS file and the profile each named by `-o`:
  exit 1, the message, the file's bytes unchanged; the image by its `\\?\` spelling: exit 1, bytes
  unchanged.
- `README.md` (the `-o` line) and `docs/design/known-limitations.md` (the guard's sentence).
