# Requirements

The source of truth for behaviour. Code follows this file, not the reverse. A behaviour change is
first an edit here (status `draft`), then a test, then code (status `implemented`), and the design
note of its area changes in the same task (the kit's rules "Requirements first" and "Design
notes"). Until 2026-10-02 this role was `docs/specification.md`'s; the specification was split
into this file, `docs/decisions/` and `docs/design/` (ADR 0001).

Rules for entries:

- IDs are `R-NNN`, assigned once, never reused. A dropped requirement keeps its ID with status
  `dropped`. Gaps in the numbering are deliberate: each block of ten is one area.
- Status is one of `draft`, `accepted`, `implemented`, `dropped`. `implemented` means a test
  named `R###_...` exists in `AstroPhotoAnalyzer.Tests` or `AstroPhotoAnalyzer.Wpf.Tests`
  (`RepoInvariantTests` checks it both ways). `accepted` means the behaviour is agreed and in the
  code, and its tests do not carry the ID yet; that is the state of most rows since the split of
  2026-10-02, and a row moves to `implemented` when its area is next touched and its tests are
  renamed.
- Describe observable behaviour, with one concrete example that includes numbers. No adjectives.
- Error behaviour and the exit code are requirements too.
- Thresholds are quoted by their `Thresholds` name and their value on 2026-10-02; the constant in
  `Thresholds.cs` is the value, this file is the meaning.
- The examples quote the console's output on the golden scenes (`AstroPhotoAnalyzer.Tests/Golden/`)
  and the figures of the reference image `de_printat.png` (`docs/validation.md`).

The explanations behind each row (how, why this way, what was measured) are in `docs/design/`
and `docs/decisions/`; the user documentation of the same behaviour, in Romanian, is `README.md`.

## Inputs

| ID | Status | Requirement |
| --- | --- | --- |
| R-010 | accepted | The reader is chosen by the file's extension, never by sniffing its content: `.fit`, `.fits`, `.fts` go to the hand-written FITS reader; `.tif`, `.tiff`, `.png`, `.jpg`, `.jpeg` to ImageSharp. Any other extension is an error naming it and the accepted ones (`format neacceptat: '.bmp'. Se accepta ...`), exit `1`. |
| R-011 | accepted | FITS: the first HDU with NAXIS 2 or 3 is read and empty primary HDUs are skipped; BITPIX 8, 16 and 32 are integers with BZERO and BSCALE applied, -32 and -64 floats; NAXIS3 must be 1 or 3, any other count is refused with a message (exit `1`); rows are flipped, and the flip noted, when `ROWORDER = 'BOTTOM-UP'`. Example: a 3-plane float32 FITS gives a colour raster. |
| R-012 | accepted | TIFF, PNG and JPEG: colour is decoded as 16-bit RGB, mono as 16-bit grey; the bit depth and the channel count come from the format's own metadata (PNG bit depth and colour type, TIFF bits per sample and photometric interpretation, JPEG always 8); the compression is named; the ICC profile is taken from the decoded image (its metadata, or its first frame's), and never applied. Palette and multi-page files are read through ImageSharp's conversion and noted, not measured natively. Example: `TIFF 16-bit RGB, 512 x 512 (0.3 MP), necomprimat, 1.5 MB, profil ICC: sRGB test` (`Golden/dark-sky.txt`). |
| R-013 | implemented | The raster is 1 or 3 planes of floats in 0..1, row 0 at the top. Normalisation: 8-bit `/255`, 16-bit `/65535`, 32-bit integer `/4294967295`, float as is; values outside [0, 1] are clipped and their count noted, and a NaN counts as clipped, to 0, so that no NaN reaches a measurement (`RasterOps.Gamma` indexes a table by level and would throw on one). The reference channel is the green plane on colour and the only plane on mono; every single-channel measurement uses it. Every 16-bit level survives the float: `RasterOps.Level16` round-trips all 65536 values. Memory is `4 x W x H x planes` bytes: 277 MB for 23 MP RGB. |
| R-014 | accepted | The source facts travel with the raster: path, format, bit depth, float or integer, planes in the file, compression, the ICC bytes and their description (from the `desc` tag, v2 text or v4 multi-localised Unicode; none when absent or malformed), the file size in bytes, and the reader's notes (clipped values, flipped rows, palette, multi-page). |
| R-015 | implemented | A linear image is refused, not measured: when the median of the reference plane at stride 8 is below `Thresholds.LinearMedianMax` (0.02), the run stops with `EROARE: imaginea pare LINIARA (mediana 0.0040, sub 0.02): unealta masoara doar imagini finite, stretch-uite. Stretch-uieste in Siril si analizeaza rezultatul.` and exit `1` (`Golden/linear-fits.txt`); the window shows the same message on its error card. A stacked linear frame sits at 0.001 to 0.01, a finished image at 0.08 to 0.25. |
| R-016 | accepted | Colour maths: sRGB to linear and back per IEC 61966-2-1; luminance Y = 0.2126 R + 0.7152 G + 0.0722 B on linear values; L\* per CIE 1976, with the linear segment below Y = 0.008856, and its exact inverse on both segments; paper black = L\*(10^-Dmax): baryta 2.4 gives 3.6, canvas 1.5 gives 20.7, acrylic C-print 2.2 gives 5.7. The 8-bit level of a grey with a given L\*, and back, is one fixed curve, used only by the window's level-L\* table and guide. Pixels are measured as written and assumed sRGB. |
| R-017 | accepted | Percentiles use numpy's default linear interpolation between ranks, as the acceptance numbers were made with numpy. The random source is a seeded xorshift64\*, so the noise and plateau tiles are the same on every runtime and every run. |
| R-018 | implemented | WCS from a FITS header: `CTYPE1` starting `RA---TAN` and `CTYPE2` starting `DEC--TAN` (a `-SIP` suffix is accepted and its terms ignored: measured under one 32 px patch at the frame's edge, ADR 0025), `CRPIX1/2`, `CRVAL1/2`, and the linear part as `CD1_1..CD2_2`, or `PC1_1..PC2_2` with `CDELT1/2`, or `CDELT1/2` with `CROTA2`; any other header means no WCS, never an error. Pixel to sky is the TAN deprojection with `LONPOLE` 180 in FITS convention (1-based, row 1 at the bottom), applied through the `ROWORDER` flip so that raster coordinates (row 0 at the top) map correctly; the WCS travels on `SourceInfo.Wcs`. Example: the plate-solved FITS (5837 x 3867, `CDELT` + `PC`) puts its `CRPIX` at RA 271.5922, Dec -10.8308 and FITS pixel (1, 1) at RA 302.2599, Dec -31.9589; a header without `CTYPE` gives null. |
| R-019 | implemented | The dark-nebula catalogue: 1787 LDN rows embedded in the core (`Input/ldn.txt`: number, B1950 centre, area in square degrees, opacity class, Barnard cross-identifications; the four unnumbered rows of VizieR's table left out), precessed to J2000 on first use with the FK4-to-FK5 rotation (no E-terms). A cloud's name is `LDN n`, or `LDN n (Bm, ...)` with its Barnard numbers; its radius is that of a disc of its area. Example: LDN 42 lands within 1' of RA 263.274, Dec -25.701 and is named `LDN 42 (B78)`; LDN 621 has area 45.0 and radius 3.78 degrees. |

## Parameters

## Tones and the print-background simulation

| ID | Status | Requirement |
| --- | --- | --- |
| R-040 | accepted | Tones in levels (0..255), over every pixel: the mean per plane; the share of samples of all planes below 32 and below 64 (`DarkLevelA`, `DarkLevelB`); the percentiles 0.1, 1, 50, 90, 99, 99.9 and 100 of the reference plane at stride `PercentileStride` (2); and the background level, the median of the reference plane at stride `TonalStride` (4), which the simulation lifts (the window's "Nivelul fundalului"). Example: the reference image reads 32.2 / 29.6 / 27.9, 74.1 % below 32, 96.3 % below 64, background level 0.103. |
| R-041 | implemented | Tones in L\*, on the stride-4 subsample, through the Rec. 709 luminance of the linearised channels: the median L\*, paper black from the Dmax in use, the shares below paper black, below L\* `LowSeparationLstar` (15) and above L\* `HighlightLstar` (50), and a 101-bin histogram 0..100 in percent. These are facts of the image; the print verdict is R-044's. Example: the plate-solved FITS on baryta: L\* median 18.0, 3.1 % of pixels below paper black (L\* 9.0), 22 % below L\* 15. |
| R-042 | implemented | The level-L\* ladder (window only, Tonuri): one row per reference, sorted by L\*: the paper black of each of the three media, the chosen medium's marked `<- mediul ales` when the Dmax in use is that medium's; an explicit Dmax (R-020: one that differs from the chosen medium's) adds its own row, `negrul hartiei: Dmax explicit 2.2`, which is then the marked one, even when another medium has the same Dmax (canvas with Dmax 2.2 marks the explicit row, not acrylic's); the levels 32 and 64, the L\* thresholds 15 and 50, and the primary target of R-023 (`fundalul recomandat 0.19`, `fundalul-tinta dat 0.135`, or no row when the as-is row is primary); each with the 8-bit level of a grey of the same L\*. |
| R-043 | implemented | The simulation: one row per target of the grid `Parameters.SimulationTargets` (0.10 to 0.20 in steps of 0.01), plus the explicit target of R-023 when it is off the grid, plus the as-is row at the measured background level (gamma 1, R-040), sorted by target, the as-is row among them. For each target, gamma = ln(target) / ln(background level) on every channel of the stride-4 subsample; each row carries the target, gamma, the dust (R-044, L\*), the sky (R-044, L\*), the share of the frame's 32 px patches below paper black (`negru pur`), the shares of pixels below L\* 15 and above L\* 50, and `print-safe` when the dust is at or above paper black. The recommended row is the lowest-target row, the as-is row included, that is print-safe and whose sky is at or above L\* `LowSeparationLstar` (15), the visibility threshold (ADR 0029), whether its target is below or above the measured level; none when no row is. Anexa B also gives the target at which the sky reaches that threshold (`cerul ajunge la pragul de vizibilitate L* 15 la 0.148`), interpolated on the same ladder as the exact target. With it the core reports the exact target that puts the dust on paper black, interpolated on a ladder of lifts `ExactTargetStep` (0.01) apart between `ExactTargetLo` (0.05) and `ExactTargetHi` (0.60) (written `> 0.60` when 0.60 does not reach it, and `<= 0.05` when 0.05 already does, since the ladder does not go lower), the same exact target at Dmax minus and plus `DmaxSensitivityStep` (0.1), and the lowest Dmax at which the as-is image is print-safe (`Dmax de la care trece asa cum e`: the Dmax whose paper black equals the as-is dust L\*). A background of 0 or 1 gives the as-is row only. The report calls it a simulation, not what Siril will produce. Example: the plate-solved FITS (level 0.1716) on baryta: as-is dust 7.9, sky 17.6, 3.7 % of patches pure black, not safe; 0.19: dust 9.6, sky 19.7, safe and recommended; exact 0.184; at Dmax 1.9 / 2.1: 0.205 / 0.163; passes as is from Dmax 2.06. |
| R-044 | implemented | The dust and the sky, measured on patches of `Thresholds.DustPatchPx` (32) x 32 image pixels of the stride-4 subsample (8 x 8 samples; partial patches at the right and bottom edges dropped), each patch's value being the L\* of its mean linear luminance, so that noise and isolated pixels cannot move it. With a WCS (R-018) the patches are classed once, on the image as it is, relative to the galactic band (ADR 0026): the band is |b| < `BandGalacticLatitudeDeg` (10); the sky model is the median of the outside-band patches on cells of `SkyModelCellPatches` (20; cells under `SkyModelCellMinPatches` (20) sky patches take the nearest cell's value), interpolated and smoothed on `SkyModelSmoothPatches` (3); the band's local level is a median over `BandLocalWindowPatches` (15) smoothed on `BandLocalSmoothPatches` (2); a patch is dust when `DustDepthLstar` (5) under the local level in the band or under the sky model anywhere, bright cloud when in the band and `BrightCloudLstar` (10) over the local level, peak when among the brightest `PeakFraction` (0.1 %), band otherwise in the band or when `BrightCloudLstar` over the sky model outside it, sky otherwise. The dust is the `DustClassFraction` (25 %) percentile of the dust patches, the sky the median of the sky patches; the method is `clase` and Anexa B gives the five fractions. The classes need the band and the outside sky each at or above `BandMinFraction` (10 %) of the patches; otherwise, and without a WCS, the dust is the `DustAreaFraction` (1 %) percentile of all patches, the sky the median of all patches, and the method is named `fara WCS`, `fara banda galactica in cadru` or `cadrul e in intregime in banda`. With a WCS, every catalogued cloud (R-019) whose disc holds a patch is found (a patch is the cloud's when its centre lies within the disc), and every cloud with at least `DustCloudMinPatches` (9) patches is a row (name, patches, the `DustCloudFraction` (10 %) percentile of its patches, its own exact target from the ladder of R-043, written `<= 0.05` or `> 0.60` at the ladder's ends), darkest first, whatever the method. The same statistics are recomputed on every lifted row of R-043 over the same patch sets. The verdict of the background section (R-092): Problem when the as-is sky is below paper black, Attention when only the as-is dust is, Ok otherwise. Example: the plate-solved FITS: band 33 % of the patches, dust 9.4 % (2062 of 21 840), sky 65 %; dust L\* 7.9, sky 17.6; 397 clouds found, 114 rows; LDN 42 (B78): 11 patches, L\* 1.0. |
| R-045 | implemented | The print preview (window only, R-131): on the subsample of the image whose longest side is at most `Thresholds.PreviewMaxSide` (1600) px, lifted with a row's gamma (gamma 1 for the as-is row), the core returns the lifted image and one class per pixel: `under paper black`, `under L* 15` (and not under paper black) or neither, from the same L\* as R-041. Example: a flat 0.08 raster at gamma 1 is entirely `under paper black` on baryta; at the gamma that lifts it to 0.19 it is entirely neither. |

## Stars and print size

| ID | Status | Requirement |
| --- | --- | --- |
| R-070 | accepted | Stars: a candidate is a pixel of the reference plane above the plane mean + `StarCandidateAboveMean16` (3000/65535), not above `StarMaxPeak16` (60000/65535, saturated), and the maximum, ties allowed, of its 25 x 25 window (`StarWindow`). Base = the median of the window's 96 border pixels; amplitude = peak - base, at least `StarMinAmplitude16` (3000/65535). The width at half maximum is measured on the horizontal and the vertical line through the peak, the crossing interpolated linearly; a star is kept when both widths are within `StarFwhmMin` (0.8) and `StarFwhmMax` (15) px, and its FWHM is their mean. The median, Q1 and Q3 need `StarMinCount` (20) stars, `n/a` below. Effective detail = width / median FWHM. Example: the reference image: 7166 stars, median 3.13 px (Q1 2.87, Q3 3.49). |
