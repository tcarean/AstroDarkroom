# Requirements

The source of truth for behaviour. Code follows this file, not the reverse. A behaviour change is
first an edit here (status `draft`), then a test, then code (status `implemented`), and the design
note of its area changes in the same task (the kit's rules "Requirements first" and "Design
notes"). Until 2026-10-02 this role was `docs/specification.md`'s; the specification was split
into this file, `docs/decisions/` and `docs/design/` (ADR 0001).

Rules for entries:

- IDs are `R-NNN`, assigned once, never reused. A dropped requirement keeps its ID with status
  `dropped`. Gaps in the numbering are deliberate: each block of ten is one area.
- Status is one of `draft`, `accepted`, `implemented`, `dropped`. `implemented` means a test
  named `R###_...` exists in `AstroPhotoAnalyzer.Tests` or `AstroPhotoAnalyzer.Wpf.Tests`
  (`RepoInvariantTests` checks it both ways). `accepted` means the behaviour is agreed and in the
  code, and its tests do not carry the ID yet; that is the state of most rows since the split of
  2026-10-02, and a row moves to `implemented` when its area is next touched and its tests are
  renamed.
- Describe observable behaviour, with one concrete example that includes numbers. No adjectives.
- Error behaviour and the exit code are requirements too.
- Thresholds are quoted by their `Thresholds` name and their value on 2026-10-02; the constant in
  `Thresholds.cs` is the value, this file is the meaning.
- The examples quote the console's output on the golden scenes (`AstroPhotoAnalyzer.Tests/Golden/`)
  and the figures of the reference image `de_printat.png` (`docs/validation.md`).

The explanations behind each row (how, why this way, what was measured) are in `docs/design/`
and `docs/decisions/`; the user documentation of the same behaviour, in English, is `README.md`.

## Inputs

| ID | Status | Requirement |
| --- | --- | --- |
| R-010 | accepted | The reader is chosen by the file's extension, never by sniffing its content: `.fit`, `.fits`, `.fts` go to the hand-written FITS reader; `.tif`, `.tiff`, `.png`, `.jpg`, `.jpeg` to ImageSharp. Any other extension is an error naming it and the accepted ones (`format neacceptat: '.bmp'. Se accepta ...`), exit `1`. |
| R-011 | implemented | FITS: the first HDU with NAXIS 2 or 3 is read and empty primary HDUs are skipped; BITPIX 8, 16 and 32 are integers with BZERO and BSCALE applied, -32 and -64 floats; NAXIS3 must be 1 or 3, any other count is refused with a message (exit `1`); the rows are always flipped, the file's first row becoming the raster's last, as Siril shows every FITS whatever `ROWORDER` says (ADR 0049); a `TOP-DOWN` keyword is noted as ignored, `BOTTOM-UP` or none is not remarked. Example: a 3-plane float32 FITS gives a colour raster; a 2 × 3 file whose rows hold 0, 0.1 and 0.2 has 0.2 in the raster's top row, with `ROWORDER = 'TOP-DOWN'` as without the keyword. |
| R-012 | accepted | TIFF, PNG and JPEG: colour is decoded as 16-bit RGB, mono as 16-bit grey; the bit depth and the channel count come from the format's own metadata (PNG bit depth and colour type, TIFF bits per sample and photometric interpretation, JPEG always 8); the compression is named; the ICC profile is taken from the decoded image (its metadata, or its first frame's), and never applied. Palette and multi-page files are read through ImageSharp's conversion and noted, not measured natively. Example: `TIFF 16-bit RGB, 512 x 512 (0.3 MP), necomprimat, 1.5 MB, profil ICC: sRGB test` (`Golden/dark-sky.txt`). |
| R-013 | implemented | The raster is 1 or 3 planes of floats in 0..1, row 0 at the top. Normalisation: 8-bit `/255`, 16-bit `/65535`, 32-bit integer `/4294967295`, float as is; values outside [0, 1] are clipped and their count noted, and a NaN counts as clipped, to 0, so that no NaN reaches a measurement (`RasterOps.Gamma` and `LiftTable` index a table by level and would throw on one). The reference channel is the green plane on colour and the only plane on mono; every single-channel measurement uses it. Every 16-bit level survives the float: `RasterOps.Level16` round-trips all 65536 values. Memory is `4 x W x H x planes` bytes: 277 MB for 23 MP RGB. |
| R-014 | accepted | The source facts travel with the raster: path, format, bit depth, float or integer, planes in the file, compression, the ICC bytes and their description (from the `desc` tag, v2 text or v4 multi-localised Unicode; none when absent or malformed), the file size in bytes, and the reader's notes (clipped values, an ignored `TOP-DOWN` row order, palette, multi-page). |
| R-015 | implemented | A linear image is refused, not measured: when the median of the reference plane at stride 8 is below `Thresholds.LinearMedianMax` (0.02), the run stops with `EROARE: imaginea pare LINIARA (mediana 0.0040, sub 0.02): unealta masoara doar imagini finite, stretch-uite. Stretch-uieste in Siril si analizeaza rezultatul.` and exit `1` (`Golden/linear-fits.txt`); the window shows the same message on its error card. A stacked linear frame sits at 0.001 to 0.01, a finished image at 0.08 to 0.25. |
| R-016 | accepted | Colour maths: sRGB to linear and back per IEC 61966-2-1; luminance Y = 0.2126 R + 0.7152 G + 0.0722 B on linear values; L\* per CIE 1976, with the linear segment below Y = 0.008856, and its exact inverse on both segments; paper black = L\*(10^-Dmax): baryta 2.4 gives 3.6, canvas 1.5 gives 20.7, acrylic C-print 2.2 gives 5.7. The 8-bit level of a grey with a given L\*, and back, is one fixed curve, used only by the window's level-L\* table and guide. Pixels are measured as written and assumed sRGB. |
| R-017 | implemented | Percentiles use numpy's default linear interpolation between ranks, as the acceptance numbers were made with numpy. The random source is a seeded xorshift64\*, so the noise and plateau tiles are the same on every runtime and every run. |
| R-018 | implemented | WCS from a FITS header: `CTYPE1` starting `RA---TAN` and `CTYPE2` starting `DEC--TAN` (a `-SIP` suffix is accepted and its terms ignored: measured under one 32 px patch at the frame's edge, ADR 0025), `CRPIX1/2`, `CRVAL1/2`, and the linear part as `CD1_1..CD2_2`, or `PC1_1..PC2_2` with `CDELT1/2`, or `CDELT1/2` with `CROTA2`; any other header means no WCS, never an error. Pixel to sky is the TAN deprojection with `LONPOLE` 180 in FITS convention (1-based, row 1 at the bottom), applied through the reader's flip (the raster's row 0 is the file's last row, whatever `ROWORDER` says, ADR 0049) so that raster coordinates (row 0 at the top) map correctly; the WCS travels on `SourceInfo.Wcs`. Example: the plate-solved FITS (5837 x 3867, `CDELT` + `PC`) puts its `CRPIX` at RA 271.5922, Dec -10.8308 and FITS pixel (1, 1) at RA 302.2599, Dec -31.9589; a header without `CTYPE` gives null. |
| R-019 | implemented | The dark-nebula catalogue: 1787 LDN rows embedded in the core (`Input/ldn.txt`: number, B1950 centre, area in square degrees, opacity class, Barnard cross-identifications; the four unnumbered rows of VizieR's table left out), precessed to J2000 on first use with the FK4-to-FK5 rotation (no E-terms). A cloud's name is `LDN n`, or `LDN n (Bm, ...)` with its Barnard numbers; its radius is that of a disc of its area. Example: LDN 42 lands within 1' of RA 263.274, Dec -25.701 and is named `LDN 42 (B78)`; LDN 621 has area 45.0 and radius 3.78 degrees. |

| R-024 | implemented | The console and the window check only the syntax of each value, with the invariant culture; the window says to use the point (`... nu e un numar (foloseste punctul ca separator zecimal)`). What the syntax lets through but no analysis can use, NaN and infinity (`double.Parse` reads `NaN`, `Infinity` and `-Infinity`; the applications' range checks are false on NaN), is refused by the core's `Parameters.Validate()`, one Romanian message per parameter (`Dmax`, `distanta de privire`, `latimea de print`, `raportul de aspect`, `passepartout-ul`, `rama`; the target background keeps R-023's), before any reading, so the console (`EROARE: ` in front, exit `1`) and the window show the same words. Example: `--dmax NaN` prints `EROARE: Dmax trebuie sa fie un numar; a primit NaN, care nu e un numar` and exits `1`; `NaN` in the window's distance field shows `distanta de privire trebuie sa fie un numar; a primit NaN, care nu e un numar`. |

The console prints the core's message and exits `1` before reading the image; the window shows the same message and does not run. Example: `--passepartout 5 --frame 3` is refused, `--passepartout 0 --frame 3` accepted. |
| R-026 | implemented | The window's distance, aspect, target-background, passepartout and frame fields carry help texts (`DistanceHelp`, `AspectHelp`, `TargetBgHelp`, `PassepartoutHelp`, `FrameHelp`), as tooltips on the field and its label: two to four paragraphs separated by a blank line, every number interpolated from `Thresholds` or `Parameters`. The distance text says what the size test does with it (and that without stars it sets the pixel-grid floor), that empty means 1.5 x each size's own diagonal and then no size is recommended, and where 1.5 comes from (1 x is the lens's perspective, 2 x gallery practice; about 37 degrees subtended). The aspect text says that empty means the native ratio with no crop and that it is for labs with fixed formats. The target-background text says what the level is for, where a screen sky (`ScreenBackgroundLo` to `ScreenBackgroundHi`, 0.05 to 0.10) and a print sky (`PrintBackgroundLo` to `PrintBackgroundHi`, 0.15 to 0.25) sit, how the background is measured and used (gamma = ln(target) / ln(background), a simulation), and where 0.19 comes from. |
| R-027 | implemented | `--wcs <file.fit>` (the window: the field `WCS din FITS (optional)` under the parameters): the header of that FITS lends its WCS (R-018) to the image analysed, which must have the same width and height; a FITS whose header has no WCS, a different size, or a file that cannot be read is an error naming `--wcs` and exits `1` (`EROARE: --wcs: <reason>`); on a FITS input the lent WCS replaces the file's own. Example: `poza.png --wcs stack.fit` with a 5837 x 3867 PNG and the plate-solved FITS gives the PNG the FITS's clouds. |
| R-028 | implemented | The Dmax from an ICC profile (ADR 0030): `--icc <file>` (the window: the button `Din profil ICC...` beside the Dmax field, R-132) reads a printer profile (class `prtr`, an RGB or CMYK device; v2 `lut8`/`lut16` or v4 `lutAToB` tables) and takes as Dmax -log10(Y) of the device black (every channel 0 on RGB, every ink at 1 on CMYK) through the profile's relative colorimetric table, that is, relative to paper white, rounded to two decimals. It replaces the medium's Dmax, and Anexa F names the profile by its `desc` tag (the file name without one): `Dmax 1.52 (din profilul ICC "Hartie de test")`. The intent is always relative colorimetric, never the header's or the perceptual one, whose black is the same L\* 3.14 for every profile. A CMYK profile is read with a note that a real printer lays less ink; the note is in the window's list and in Anexa F, under the parameters (`nota profilului: profil CMYK: ...`). The chosen medium keeps its name in the report; only its Dmax is replaced. A Dmax outside (0, `Thresholds.DmaxMax` (4)], the range `--dmax` accepts, is refused as a damaged profile. What cannot be read says why and nothing is analysed: `EROARE: --icc: <reason>`, exit `1`, with the reasons `nu e un profil ICC`, `nu e un profil de imprimanta (clasa 'mntr'); ...`, `profil de imprimanta 'GRAY': se citesc doar profilele RGB si CMYK`, `fisierul nu se poate citi: ...`, `profilul nu se poate citi: ...`, `tabela colorimetrica a profilului nu da un negru intre 0 si albul hartiei; profilul e probabil stricat`, `profilul da Dmax 4.25, in afara intervalului (0, 4]; profilul e probabil stricat`. `--icc` together with `--dmax` is refused at parsing (`--icc si --dmax dau amandoua Dmax-ul hartiei; alege unul`). The installed profiles are the printer profiles (`.icc`, `.icm`) of the Windows colour folder, `<System>\spool\drivers\color`, by name; an absent folder is an empty list. Example: a profile whose colorimetric black is L\* 20 gives Dmax 1.52 and paper black L\* 20.1; the lab's baryta profile gives 2.41 (V-006). |

## Tones and the print-background simulation

| ID | Status | Requirement |
| --- | --- | --- |
| R-040 | implemented | Tones in levels (0..255), over every pixel: the mean per plane; the share of samples of all planes whose 8-bit level, the one an 8-bit export would write (`RasterOps.Level8`, halves rounded to even), is under 32 and under 64 (`DarkLevelA`, `DarkLevelB`), on every format, so that on an 8-bit TIFF, PNG or JPEG the level 32 itself is not "sub nivelul 32" (ADR 0043); the percentiles 0.1, 1, 50, 90, 99, 99.9 and 100 of the reference plane at stride `PercentileStride` (2); and the background level, the median of the reference plane at stride `TonalStride` (4), which the simulation lifts (the window's "Nivelul fundalului"). Example: the reference image reads 32.2 / 29.6 / 27.9, 74.1 % below 32, 96.3 % below 64, background level 0.103. |
| R-041 | implemented | Tones in L\*, on the stride-4 subsample, through the Rec. 709 luminance of the linearised channels: the median L\*, paper black from the Dmax in use, the shares below paper black, below L\* `LowSeparationLstar` (15) and above L\* `HighlightLstar` (50), and a 101-bin histogram 0..100 in percent. These are facts of the image; the print verdict is R-044's. Example: the plate-solved FITS on baryta: L\* median 18.0, 3.1 % of pixels below paper black (L\* 9.0), 22 % below L\* 15. |
| R-042 | implemented | The level-L\* ladder (window only, Tonuri): one row per reference, sorted by L\*: the paper black of each of the three media, the chosen medium's marked `<- mediul ales` when the Dmax in use is that medium's; an explicit Dmax (R-020: one that differs from the chosen medium's) adds its own row, `negrul hartiei: Dmax explicit 2.2` (`negrul hartiei: Dmax din profilul ICC 2.41` when it was read from a profile, R-028), which is then the marked one, even when another medium has the same Dmax (canvas with Dmax 2.2 marks the explicit row, not acrylic's); the levels 32 and 64, the L\* thresholds 15 and 50, and the primary target of R-023 (`fundalul recomandat 0.19`, `fundalul-tinta dat 0.135`, or no row when the as-is row is primary); each with the 8-bit level of a grey of the same L\*. |
| R-043 | implemented | The simulation: one row per target of the grid `Parameters.SimulationTargets` (0.05 to 0.20 in steps of 0.01; ADR 0034), plus the explicit target of R-023 when it is off the grid, plus the as-is row at the measured background level (gamma 1, R-040), sorted by target, the as-is row among them. For each target, gamma = ln(target) / ln(background level) on every channel of the stride-4 subsample; each row carries the target, gamma, the dust (R-044, L\*), the sky (R-044, L\*), the share of the frame's 32 px patches below paper black (`negru pur`), the shares of pixels below L\* 15 and above L\* 50, and a mark: `print-safe` when the dust is at or above paper black and the sky at or above L\* `LowSeparationLstar` (15), the visibility threshold (ADR 0029); `cer sub L* 15` when the dust is at or above paper black and the sky is not; nothing when the dust is under paper black. The sky is compared as the table prints it, to one decimal, so a row that shows `15.0` passes. The recommended row is the lowest-target row, the as-is row included, marked `print-safe`, whether its target is below or above the measured level; none when no row is. Example: the plate-solved FITS on baryta at Dmax 2.4: 0.11 (dust 3.6, sky 10.0) no mark, 0.12 (dust 4.1, sky 11.3) `cer sub L* 15`, 0.15 (dust 6.1, sky 15.0) `print-safe` and recommended. Anexa B also gives the target at which the sky reaches that threshold (`cerul ajunge la pragul de vizibilitate L* 15 la 0.148`), interpolated on the same ladder as the exact target. With it the core reports the exact target that puts the dust on paper black, interpolated on a ladder of lifts `ExactTargetStep` (0.01) apart between `ExactTargetLo` (0.05) and `ExactTargetHi` (0.60) (written `> 0.60` when 0.60 does not reach it, and `<= 0.05` when 0.05 already does, since the ladder does not go lower; a given target outside the ladder gets its row and feeds no series, so the two bounds hold whatever was given, ADR 0040), the same exact target at Dmax minus and plus `DmaxSensitivityStep` (0.1), and the Dmax from which the as-is dust reaches paper black (`praful ajunge pe negrul hartiei de la Dmax 2.06`: the Dmax whose paper black equals the as-is dust's L\*; `praful nu ajunge pe negrul hartiei la niciun Dmax (e la L* 0)` for a dust at L\* 0); it is the dust's figure alone, so when the as-is sky is under L\* `LowSeparationLstar` the same sentence adds `; asa cum e, nicio hartie nu face imaginea print-safe: cerul e sub L* 15, iar remediul e ridicarea fundalului la stretch` (ADR 0043).
