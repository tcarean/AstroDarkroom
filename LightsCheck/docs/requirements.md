# Requirements

The source of truth for behaviour. Code follows this file, not the reverse. A behaviour change is
first an edit here (status `draft`), then a test, then code (status `implemented`).

Rules for entries:

- IDs are `R-NNN`, assigned once, never reused. A dropped requirement keeps its ID with status
  `dropped`. Gaps in the numbering are deliberate: each block of ten is one area.
- Status is one of `draft`, `accepted`, `implemented`, `dropped`. `implemented` means a test named
  `R###_...` exists in a test project under `tests/` (`RepoInvariantTests` checks it both ways; it
  reads the sources of the projects it cannot reference, ADR 0008).
- Describe observable behaviour, with one concrete example that includes numbers. No adjectives.
- Error behaviour and the exit code are requirements too.

The explanations behind each row (why this way, what was measured) are in `docs/design/` and
`docs/decisions/`; the user documentation of the same behaviour, in English, is `README.md`.

## Console contract

| ID | Status | Requirement |
| --- | --- | --- |
| R-001 | implemented | Every run prints `lightscheck <version>` as its first line and `Copyright (C) 2026 Tudor Carean` as its second, for `--help`, for a session and on a failed run. The version is the `<Version>` of `Directory.Build.props`; there is no `--version` flag. The banner is written before the arguments are parsed, so no option can suppress or move it. |
| R-002 | implemented | The input is a Siril session folder (ADR 0004). The lights are the frames of its `lights/` subfolder when that exists (empty, it is an error naming it, never a fallback to the root, which holds the stacked results); without `lights/`, the frames directly in the folder. The biases are the frames of `biases/`, optional; the darks are the frames of `darks/`, optional, counted and never opened (R-042). The frames of a folder are its camera raws (`.nef`, `.cr2`, `.cr3`, `.arw`, `.dng`, `.raf`, `.pef`) when there are any, otherwise its FITS files (`.fit`, `.fits`, `.fts`), sorted by file name ignoring case; the two kinds are never mixed. A missing folder or a folder without frames exits `1` with a message naming the folder. Example: a folder with `lights/DSC_0001.NEF` to `DSC_0087.NEF` and `biases/` with 30 raws reports `lights\ (87 cadre .NEF)` and `biases\ (30 cadre .NEF)`. |
| R-003 | implemented | For every light the console prints a row with its index, file name, time of capture (`HH:mm:ss`), exposure in seconds (one decimal), ISO, f-number, focal length and the pause before it; a field the file does not carry prints `-`. The metadata comes from libraw on a raw (shutter, ISO, timestamp, focal length, aperture, camera, the lens's ID, mount and name, R-065, the 35 mm-equivalent focal length and the visible mosaic's size, R-066) and from the header on a FITS (`EXPTIME`, `ISOSPEED`, `DATE-OBS`, `FOCALLEN`, `INSTRUME`, `XPIXSZ`). A frame that cannot be read, or a `.fit` that does not start with `SIMPLE` (the reader's own message, `FITS: the file does not begin with SIMPLE.`, R-008), prints `eroare: <message>` in its row and an `ATENTIE` line in the header, and the run exits `1`; the other frames are still listed. Example: on the Veil session of 2026-10-06 row 1 reads `DSC_0001.NEF  23:35:03  120.2  1600  2.8  135 mm`. |
| R-004 | implemented | `--help`, `-h` or no arguments prints the usage, the GPLv3 warranty disclaimer (`RunReport.WarrantyLines`) and a pointer to `LICENSE`, and exits `0`. An unknown option or a second folder exits `1` with a message naming the argument. `--pixel UM` takes a finite number greater than 0; `--pixel NaN`, `--pixel Infinity` and `--pixel 0` exit `1` with the same message as `--pixel abc` (`SeriesOptions.PixelSizeIsValid`, the one check the console and the window share). Without `--pixel` the option is null and the series run takes the pixel size from the files or the raws (R-066). |
| R-005 | implemented | The console formats and parses numbers with `.` as the decimal separator whatever the Windows culture (`<InvariantGlobalization>` in `lightscheck.runtimeconfig.json`: `0.5`, never `0,5`). `LightsCheck.Tests` runs under the same switch, so the golden texts compare against the console's formatting, not the test machine's culture. |
| R-006 | implemented | The cadence of the session: the start of the first timed frame, the end of the last (start plus exposure), the span between them, the integration (the sum of the exposures), the duty (integration over span, in percent) and, per frame, the pause in seconds between the end of the previous timed frame and its start. A frame without a time or an exposure is left out and gets no pause, as does the frame after it. Example: three frames of 120 s started 150 s apart give a span of 420 s, an integration of 360 s, a duty of 86 % and pauses of 30 s. |

## Reading frames

| ID | Status | Requirement |
| --- | --- | --- |
| R-007 | implemented | A camera raw is dispatched by extension to libraw and read undebayered: the visible CFA mosaic at the original ADU scale, the exact white and black levels (the median of the four channel blacks), the colour order from `filters` and `cdesc`, and the shot metadata. The metadata-only load (`LoadInfo`) returns the same shot fields as the full load, without pixels. No field of `RawReader` is a libraw type, so a FITS run never loads the libraw assembly; when the assembly or its native DLLs are missing a raw run exits `1` with a message naming what is missing. A raw libraw cannot open or unpack (a `.NEF` that is not a raw at all) fails with `InvalidDataException` whose message is Romanian and names the file (`<file>: libraw nu poate citi fisierul`; libraw's own words only as the inner exception), the type a corrupt FITS gives (R-008), so `--frame N` on it exits `1` with `EROARE: <file>: ...` instead of crashing, and the inventory and series runs list it as unreadable as before. A FITS never goes to libraw. Example: `DSC_0001.NEF` of the Veil session of 2026-10-06 reads as a 6016 x 4016 mosaic on the scale 150 .. 4095 ADU (`libraw (exact)`), channel medians above black R 27, G1 126, G2 126, B 144, with 120.2 s at ISO 1600, f/2.8, 135 mm and the lens ID 74 on `Nikon F` (R-065) as its metadata. |
| R-008 | implemented | A FITS light is read by the hand-rolled reader copied from FlatCheck (ADR 0003): BITPIX 8, 16, 32, -32, -64 with `BZERO` / `BSCALE`, a colour cube averaged over its planes, `BAYERPAT` shifted by `XBAYROFF` / `YBAYROFF` and by one row under `ROWORDER = 'BOTTOM-UP'` on an even height. A corrupt FITS fails with `InvalidDataException` naming the problem. A FITS whose data area is shorter than its header declares (the product of the `NAXISn` times `|BITPIX| / 8`, checked for every HDU before a sample is read; a copy cut mid-transfer) fails with `InvalidDataException` and `FITS: date trunchiate: octeti de pixeli anuntati de header: <n>, in fisier doar <m>.`; one whose last HDU lacks only its padding to 2880 bytes still loads. Taken from FlatCheck's R-009 (b9b20a6, 469da9b). Both reads of a file dispatched to the FITS reader, the full load (`ImageLoader.Load`) and the metadata-only read (`ImageLoader.LoadInfo`, the inventory's), refuse the same files with the same `InvalidDataException` and message (FlatCheck's R-008 and ADR 0057, taken 2026-10-27, ADR 0027): `FITS: the file does not begin with SIMPLE.` (`FITS: fisierul nu incepe cu SIMPLE.`) for a file whose first card is not `SIMPLE` (an empty file, one shorter than the 8 bytes of a keyword, 100 bytes of zeros, a whole 2880-byte block whose first card is `NAXIS`), and `FITS: incomplete header.` (`FITS: header incomplet.`) for a header that begins with `SIMPLE` but ends before `END` (100 bytes, or one block without `END`); the metadata read never answers with an empty header, and `FrameInfo.Read` no longer guesses an error from one. Example: a 100-byte `.fit` of zeros in `lights/` prints `error: FITS: the file does not begin with SIMPLE.` in its inventory row (`eroare: FITS: fisierul nu incepe cu SIMPLE.`), where it printed `not a FITS file (it does not begin with SIMPLE)` until 2026-10-27. The tests of the copied reader carry no ID; the two refusals' tests are `R008_`. |
| R-065 | implemented | The lens of a raw is read on every mount as FlatCheck's R-108 reads it (ADR 0025): the ID by mount (`LensId`: Nikon's `LensIDNumber` when above 0; otherwise the MakerNote's `LensID`, taken only when the MakerNote names a mount other than Nikon's and the value is above 0 and fits 31 bits, since on a Nikon body that field holds the 8-byte LensData signature, 5356031691206446338 on a D3300; nothing with an unknown mount), the mount as libraw names it (`LensMount`: `Nikon F`, `Canon EF`, `Canon RF`, `Sony E`, `Pentax K` and the other labels of `RawReader.MountLabel`; the lens's mount, the camera's when the lens's is 0; null for a mount without a label), the lens's name as the camera wrote it (`LensName`, EXIF LensModel, trimmed; null when empty) and its range (the focal ends from the MakerNote, else from the top of `LensInfo`; the aperture from the MakerNote's `MaxAperture4MinFocal`, else the top field, else the MakerNote's `MaxAperture` only on a prime or when the shot's focal length is the lens's shortest, within 1 mm or 5 %), each null when libraw gives 0 or empty; a failure in the lens block leaves the lens fields null and the rest as read. `FrameInfo` carries the three lens fields. `.pef` (Pentax) is the seventh raw extension (R-002). The inventory's `lens` line (`obiectiv` in Romanian) puts the shot's focal length and f-number first, then the lens as its chip declares it (`lens 135 mm f/2.0`), then the lens as the raw names it: the name in quotes when known, followed by the ID and the mount in one parenthesis, `"EF50mm f/1.4 USM" (ID 198, Canon EF)`; without a name, the ID with the mount, `ID 74 (Nikon F)`; a mount without an ID or a name prints nothing; the first readable frame with a focal length, an ID or a name is the one read. Example, on frames fabricated with the values libraw 0.21.1 gave FlatCheck on 2026-10-26 (`InventoryReportTests`, `RawReaderTests`): a Canon EOS 7D Mark II at f/4 with `LensID` 198, `EF50mm f/1.4 USM`, 50 mm, `MaxAperture4MinFocal` 0 and `MaxAperture` 1.414 reads `50 mm f/4.0 (as shot), lens 50 mm f/1.4, "EF50mm f/1.4 USM" (ID 198, Canon EF)`; a Pentax K-70 with 2263, no name and no range reads `18 mm f/5.6 (as shot), ID 2263 (Pentax K)`; a Sony ILCE-7M3 with the name alone reads `32 mm f/4.0 (as shot), lens 16-35 mm f/2.8, "FE 16-35mm F2.8 GM" (Sony E)`; the Veil session's D3300 with the Samyang reads `135 mm f/2.8 (as shot), lens 135 mm f/2.0, ID 74 (Nikon F)` (it read `Nikon ID 74` until 2026-10-27); a FITS frame reads `135 mm (as shot)` as before. |
| R-066 | implemented | The pixel size the series run converts pixels to arcseconds with is chosen in this order (`PixelPitch.Choose`, ADR 0026): the first file that carries `XPIXSZ` (`from the file (XPIXSZ)` / `din fisier (XPIXSZ)`); else the value typed, `--pixel` or the window's field (`entered` / `introdus`); else the value derived from the first raw that gives a 35 mm-equivalent focal length (`from the raw (35 mm-equivalent focal length)` / `din raw (focala echivalenta 35 mm)`); else the Nikon D3300's 3.92 um (`default, Nikon D3300` / `implicit, Nikon D3300`); the `scale` line of the report prints the value and its source. The derived value (`PixelPitch.FromCrop`) is `43.2666 mm x focal / (focal35 x sqrt(W² + H²))` in microns, with `focal` the shot's focal length, `focal35` libraw's `LensInfo.FocalLengthIn35mmFormat` (EXIF FocalLengthIn35mmFilm, an integer the camera writes from the sensor's diagonal) and `W x H` the visible mosaic; the diagonal and not the width, because the 35 mm equivalence is a ratio of diagonals, equal on a 3:2 sensor and 4 % apart on a 4:3 one. It is null when any of the four is missing or not positive: a FITS (no 35 mm figure), a raw of a body with no lens data entered (the field is 0). `LoadedFrame` and `FrameInfo` carry `FocalLength35Mm`, `WidthPx` and `HeightPx` (raw only). Example, measured 2026-10-27 on the two sessions' D3300 raws (6016 x 4016, no margins): the Veil session's 135 mm with `FocalLengthIn35mmFormat` 202 gives 4.00 um (3.9976), the Smida session's 20 mm with 30 gives 3.99 um (3.9878), against the 3.92 (23.5 mm over 6000 pixels) used until then; so the Veil scale becomes 6.11 "/px instead of 5.99 and its median move `13.29 px` reads 81.2" instead of 79.6". The goldens' FITS fixtures carry `XPIXSZ 3.92` and do not move. |

## Measuring one frame

The method is the Python prototype's (`prototype/analyze.py`); every constant is in
`Thresholds.cs` (`Th`), the reasons in `docs/design/frame-analysis.md` (ADR 0006). Figures are
in pixels of the frame and ADU above black.

| ID | Status | Requirement |
| --- | --- | --- |
| R-012 | implemented | For each of the four CFA positions, named from the file's colour order (`R`, `G1`, `G2`, `B`; `CFA[y,x]` when unknown): the median above black read at every 4th pixel of the position, the count of pixels within `Th.SaturationMargin` of the top of the scale (1 ADU on an integer scale; 1/4096 of the scale on a float 0..1 frame, as Siril writes a calibrated light), and the minimum. The brightest channel is the one with the highest median. Example: a synthetic RGGB frame with backgrounds 30 / 150 / 170 reads `R 30  G1 150  G2 150  B 170`. |
| R-013 | implemented | The green channel at full resolution (green positions kept, the others the mean of their four green neighbours; the raster as it is when the colour order is unknown), its background as the medians of 128 px tiles read at every 4th pixel and stretched back bilinearly with the grid's corners on the raster's corners (a frame smaller than a tile is one tile), and the noise as 1.4826 x the median absolute deviation of the residual in the central 2000 x 2000 window read at every 3rd pixel. Reported: the median, minimum and maximum of the tiles, the mean of the central 4 x 4 tiles and of each 3 x 3 corner. Example: a flat 150 ADU green background with 12 ADU noise reads median 150 and a sigma between 7 and 13 (the interpolation halves the noise of half the pixels). |
| R-014 | implemented | Stars are the 4-connected components of the residual smoothed by a Gaussian of 1 px that exceed `Th.DetectionSigmas` (5) x the smoothed image's sigma, with an area of 5 to 400 px. Counted: all, the bright ones (peak above 50 sigma), and the saturated components (a raw pixel within 1 ADU of the top). The 400 brightest by flux among those peaking above 20 sigma and below 0.8 of the scale get second moments in a circular window of radius 6 px around a centroid refined 3 times, negative values clipped: FWHM = 2.3548 sqrt((mxx+myy)/2), elongation = sqrt(l1/l2), angle = 0.5 atan2(2 mxy, mxx-myy) in degrees from the x axis; kept when the FWHM is in 1..15 px. Reported: the median and 90th percentile of FWHM and elongation, the fraction elongated above 1.3, the mean angle and coherence of the stars above 1.2 (doubled-angle vector mean; at least 6 voters), the median FWHM and elongation per radial zone (centre under 0.2765 of the half-diagonal, mid under 0.6082, edge beyond; at least 5 stars), and the median halo (annulus 5-10 px over core 3 px) of the 40 brightest measured stars. Example: 60 synthetic round stars of FWHM 3.0 read a median FWHM within 2.8..3.6, elongation under 1.12 and no angle; the same stars at elongation 1.8 and 80 degrees read elongation within 1.6..1.95, angle within 75..85 and coherence above 0.95. |
| R-015 | implemented | A component of more than 250 px whose bounding-box diagonal exceeds 80 px and whose area is under 0.25 of the box plus 60 px is a trail (satellite, plane), reported with its length and its top-left corner; it is not a star. Example: a 3 px wide line from (100,100) to (700,400) reads one trail of length 671. |
| R-016 | implemented | The registration list is the 600 brightest star components by flux, saturated included, each with its flux-weighted centroid; a drawn star at (500, 350) is found within 0.3 px. |
| R-017 | implemented | `lightscheck <folder> --frame N` decodes the N-th light (1 = first) and prints its measurements (R-012 to R-016) under `=== CADRU N: <file> ===`, exit `0`; N outside 1..count exits `1` naming the count, and so does a light no reader can decode (a FITS whose data is cut, a raw libraw refuses), with `EROARE: <message>`, never an unhandled exception. A FITS without an ADU scale is read at the full range of its BITPIX (0..65535 for 16 bits, 0..1 for a float frame); a raw at libraw's exact scale. |

## The series

The constants are in `Thresholds.cs` (`Th`); the dithering definitions and the verdict rules
are ADR 0007; the mechanics in `docs/design/series-analysis.md`.

| ID | Status | Requirement |
| --- | --- | --- |
| R-018 | implemented | Every measured frame is registered to the reference (the first measured frame): a vote over all offsets between the 300 brightest stars of each (bins of 8 px over +-2000 px) gives the coarse shift; four rounds of nearest-neighbour matching (tolerance 8 px, then 3 px) over the 600 registration stars feed a least-squares similarity (shift, rotation, scale). Reported: the displacement of the reference's centre in the frame (`Dx`, `Dy`, pixels; positive = the stars moved right / down), the rotation in degrees, the scale, the matched stars and the RMS residual. Fewer than 10 matches is a failed registration, and the frame has no position. Example: a field shifted by (155.9, -180.4) px and rotated 0.14 degrees is recovered within 0.1 px and 0.002 degrees. |
| R-019 | implemented | How often the dithering was done: a step between consecutive registered frames of `Th.DitherStep` (5 px; the frames shot back to back on the Veil session drifted up to 7 px) or more is a move; a pause before a frame above `Th.DitherPause` (5 s) is a pause. Reported: the moves, the pauses, the pauses without a move (a press that did nothing), the moves without a pause, a table of "frames between one move and the next" (every 1, every 2, every 3 ...), and the longest stretch without a move with its frames and minutes. Example: moves at frames 3, 5 and 7 of 8 read "every 2 frames: 2 times". |
| R-020 | implemented | How far: the median move, the count of moves per size class [5, 10), [10, 20), [20, ...) px (and in arcseconds when the scale is known), the moves along X only, Y only, or both (a component counts from `Th.AxisStep`, 3 px), and the signs of the components per axis. Example: the 41 moves of the Veil session have a median of 13.29 px = 79.6", 10 in [5, 10), 23 in [10, 20) and 8 at 20 px or more; 6 along X only, 28 along Y only, 7 on both; signs X +11 / -2, Y +11 / -24. |
| R-021 | implemented | Coverage: for every registered frame the distance to the nearest other frame; the counts of frames with another within 3, 5 and 10 px and the frames at least 10 px from every other; the distinct positions by greedy clustering at 5 and 10 px; the runs of 3 or more consecutive frames within 5 and within 10 px of the run's first frame; the span on each axis. Verdicts: hot pixels fine while no more than `Th.HotPixelRunMax` (3) consecutive frames sit within 3 px of the run's first frame (the runs above, at 3 px); walking noise fine when at least half the frames are distinct at 10 px, at least 30 % are isolated at 10 px, and each axis carries at least a quarter of the moves. Example: on the Veil session the nearest other frame is at a median 2.2 px; 70 frames have another within 3 px, 79 within 5, 86 within 10, 1 is isolated; 38 distinct positions at 5 px, 25 at 10; the longest run at 10 px is frames 61-70 (10 frames, 22 min); span X 157 px, Y 200 px; hot pixels `OK`, walking noise `INSUFICIENT` (25 of 87 distinct, 1 isolated, 7 moves on both axes). The word the report prints for walking noise also reads the drift (R-043). |
| R-022 | implemented | Each measured frame gets a class: bad at median elongation >= `Th.ElongationBad` (1.6), marginal at >= `Th.ElongationMarginal` (1.35), else good; a good frame whose median FWHM exceeds 1.3 x the session's median FWHM of the good frames becomes marginal (soft); a frame with fewer stars than 0.6 x the session's median star count becomes marginal (clouds) when it was good; a background more than 8 % away from the median of its two neighbours on each side is flagged (jump); a trail is flagged; a frame that could not be read or registered is flagged, the unreadable one classed unknown. Every flag carries the measured value and the threshold, and the report prints both. Example: elongation 1.7 reads `alungire 1.70 (prag 1.60)`. The words of every class and flag, one frame of each, are pinned by the golden `series-classes.txt` (`SessionFixture.ClassesPattern`). |
| R-023 | implemented | Trends on the good frames, the median of the first 10 against the last 10 (fewer when the session is short): FWHM, halo, green background, star count. Focus held when the FWHM moved by less than 10 %; dew suspected when the FWHM rose by more than 15 % and the halo by more than 0.02. Drift: the mean step per minute on each axis over the consecutive registered pairs that were not moves. Rotation: the registration rotation of the last registered frame minus the first, per hour, and the corner displacement that rate makes in one exposure. Example: on the Veil session the first and last 10 good frames have FWHM 3.11 / 3.11 px (+0 %) and halo 0.027 / 0.012: focus held, no dew; the drift is X -0.27, Y -0.48 px/min over 45 pairs; the rotation is 8.5 arcmin over 3 h 22 min = 2.5 arcmin/h, 0.09 px in a corner within one 120 s exposure. |
| R-024 | implemented | Noise: the read noise per CFA position from the first two biases (the clipped standard deviation of their central 600 x 600 difference over sqrt 2), the total noise of each light's channels as the clipped standard deviation of the pixel minus its 5 x 5 median in the central window, corrected by the ratio of the pair sigma to the same high-pass sigma on the bias, the shot variance as total minus read variance, the gain as sky over shot variance, the swamping ratio (shot variance over read variance) and the penalty `sqrt(1 + 1/ratio) - 1`. Reported on the first, the middle and the last measured frames; a ratio under `Th.SwampingRatioOk` (10) reads read-noise limited. Without two biases: not measured. Example: from the Veil session's biases the read noise is R 3.3, G1 2.9, G2 2.9, B 3.3 ADU; on frame 1 the red channel has sky 27 ADU, ratio 9.4 and penalty 5.2 % (read-noise limited), G1 sky 126, ratio 46.1, penalty 1.1 %; on frame 87 red has sky 37, ratio 11.4, penalty 4.3 %. |
| R-025 | implemented | The RA axis of the image: from a plate-solved FITS at the session root (`CTYPE1` starting with `RA`; RA runs along Y when `PC1_2` / `CD1_2` dominates `PC1_1` / `CD1_1`), else from the trail direction of the bad frames (the vector mean of the angles of at least `Th.TrailAxisMinFrames` (2) bad frames with coherence above 0.8; within 25 degrees of vertical = Y, of horizontal = X, stated as an assumption that the trailing is in RA), else unknown. Example: the Veil session root holds Siril's solved `result.fit`, whose RA row of the WCS matrix is dominated by Y, and the report prints `axa Y a imaginii = RA, X = DEC (plate solve (WCS))`; the synthetic session of the golden `series.txt` has no solved FITS and two frames trailed at -90 degrees, so it prints `(directia darelor (presupus: urmarirea e pe RA))` with Y. |
| R-026 | implemented | `lightscheck <folder>` measures every light in parallel (`--threads N`, default half the cores), registers them, reads the biases and prints the series report; the progress goes to stderr. The pixel scale uses the file's `XPIXSZ` when present, else `--pixel UM` when typed, else the pixel size derived from the raw, else 3.92, the D3300's (R-066).
