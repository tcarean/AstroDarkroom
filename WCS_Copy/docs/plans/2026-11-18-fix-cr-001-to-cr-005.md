## Commit 1: CR-001, CR-013, CR-014, the three paths are three files (R-019, ADR 0018)

- **R-019 (new):** the source, the destination and a new file must be three different files,
  told by the file each path opens, not by its spelling (letter case, `..`, a `\\?\` prefix, a
  short 8.3 name, a link). After both headers are read and before anything is selected or
  written, a dry run included, the run is refused with exit 1 and one of the three lines
  above. A new file that does not exist yet is none of them. Example: `copywcs solved.fit
  Stack.fit -o stack.fit` is refused and both files are left byte for byte as they were.
  R-033 gains the new refusals in its list.
- **Code:** new `src/CopyWcs.Core/FileIdentity.cs`, `FileIdentity.Same(a, b)`: opens both
  (`File.OpenHandle`, sharing everything) and compares the volume serial number and the file
  index of `GetFileInformationByHandle` (a `LibraryImport`, as `DarkTitleBar`'s; the core gets
  `AllowUnsafeBlocks` with the same comment). A file that cannot be opened is false (the read
  or the write says why); off Windows, when the call fails, or when it gives index 0, it
  compares `Path.GetFullPath` (ignoring case on Windows). `WcsCopy.Run` checks source against
  destination, then a new file against the source, then against the destination, right after
  the destination's read: a Warn line, `clock.Lap("select")`, `Done("refused: ...")`, as the
  other refusals.
- **Tests first** (red today: the run says `Copied`): `WcsCopyTests`
  `R019_Run_ANewFileThatIsTheSource_IsRefused_ADryRunToo_AndTheSourceIsLeftAsItWas`,
  `R019_Run_TheSameFileAsSourceAndDestination_IsRefusedAndWritesNothing`,
  `R019_Run_ANewFileThatIsTheDestination_IsRefusedUnderAnySpelling` (other case, `\\?\`, `..`,
  the identical string), each in both languages; `CopyWcsCliTests` exit 1 and the stderr line;
  `MainViewModelTests` the window's refusal in the console's words, the source untouched;
  `LanguageTests` three scenarios for R-023 and the words `acelasi`, `chiar`, `suprascrie`;
  `FileIdentityTests` (same path, other case, `\\?\`, `..`, two files, a missing file, an
  empty path).
- **Docs:** `run-and-console.md` (the check in the sequence; `FileIdentity.cs` in its Covers),
  `logging.md` (the three refusal reasons), `README.md` (exit codes, one sentence),
  `CLAUDE.md` layout, `CHANGELOG.md` Fixed, ADR 0018, this plan.

## Commit 2: CR-002, a close during a run waits (R-050, ADR 0019)

- **R-050 (new):** closing the window while a Preview or a Copy is in flight (X, Alt+F4, the
  taskbar) does not end the run: the window stays until the run ends, then closes by itself; a
  second close meanwhile adds nothing. The file the run writes is whole; the log holds `close
  asked while a run is in flight: the window closes when it ends`, the run's done line, then
  `the run ended: the window closes`. With no run in flight the window closes at once. R-043
  gains the two window lines.
- **Code:** `MainViewModel.IsRunning` (raised when a run starts and ends) and `RunCore`, the
  run it calls, `WcsCopy.Run` unless a test replaces it (as `MainWindow.OpenAddress`).
  `MainWindow.OnClosing`: while `IsRunning`, cancel, remember the close, log once; on
  `IsRunning` going false with a close remembered, log and `Close()`.
- **Tests first:** new `WindowCloseTests` in the window collection: a copy held in `RunCore`,
  `Close()` leaves the window open (red today: it closes at once), a second `Close()` too;
  released, the window closes and the new file equals the console's `-o` output; a close with no
  run closes at once. `WindowLoggingTests`: the two lines around the run's done line.
- **Docs:** `window.md`, `logging.md` (MainWindow row), `README.md` (window section),
  `CHANGELOG.md`, ADR 0019.

## Commit 4: CR-004, the destination's CHECKSUM is dropped (R-018, ADR 0021)

- **R-018 (new):** a copy writes the target without the destination's `CHECKSUM` card, in
  place and with `-o`, whatever the source holds: every copy changes the header (`HISTORY` at
  least), and the FITS checksum convention asks a program that changes an HDU to update the card
  or remove it. `DATASUM` stays, the data being the destination's unchanged. Nothing on screen;
  the log's `drop CHECKSUM: <card>`, in a dry run too. A dry run and a refusal leave it. Example:
  V-002's destination, forced, comes out without `CHECKSUM= '6jF39j936jE36j93'` and with
  `DATASUM = '2647693551'`. R-016's "nothing is dropped when the source has no `CTYPE1`"
  becomes "no plate-solve card", and R-042 gains the line.
- **Code:** `WcsCopy.Run` removes `CHECKSUM` after the R-016 drop; `LogSelection` logs it. The
  done line's `dropped` still counts R-016's keys, so V-002's recorded figures do not move.
- **Tests first** (red today): `WcsCopyTests` `R018_Run_ADestinationWithAChecksum_IsWrittenWithoutIt_AndKeepsItsDatasum`
  (in place and `-o`), `R018_Run_ADryRunOrARefusal_LeavesTheChecksum`; `ValidationTests`
  `R018_ACopyIntoTheRealSyQonHeader_DropsItsChecksumAndKeepsItsDatasum` (the fixture);
  `LoggingTests` the drop line.
- **Docs:** `run-and-console.md`, `logging.md`, `README.md` ("What is copied"),
  `CHANGELOG.md`, ADR 0021.

## Commit 5: CR-005, a card travels with its CONTINUE cards (R-010, R-009, ADR 0022)

- **R-010 and R-009 (amended):** a card and the `CONTINUE` cards right under it are one value:
  the copy takes them all, verbatim, in order; a destination card it replaces or drops (R-016)
  goes with the `CONTINUE` cards under it. The dry run lists a `CONTINUE` card under the card
  it continues; its count stays the keys'. Example: a source `OBJECT` of 90 characters, written
  as `OBJECT  = '...&'` and one `CONTINUE` card, reaches the destination as those two cards; a
  destination whose long `TELESCOP` had a `CONTINUE` card keeps none under the source's
  `TELESCOP= 'My Scope'`.
- **Code (`FitsHeader`):** `ValueCards(key)` (the first card of the key and the `CONTINUE`
  cards right under it) and `SetValueCards(key, cards)` (replaces that run of cards where it
  stands, or appends); `SetCard` becomes `SetValueCards(key, [card])`; `RemoveCards` and
  `CardsOf` take each card's `CONTINUE` cards with it. `WcsCopy.Run` copies through them: the
  outcome's `Cards` hold every card, `CONTINUE` ones included; the heading and the closing line
  count keys; the log's `card KEY:` line joins a value's cards with ` + `. `CLAUDE.md`'s rule
  "A card is copied verbatim" names the new call.
- **Tests first** (red today): `WcsCopyTests` `R010_Run_ALongStringValue_TravelsWithItsContinueCards`,
  `R010_Run_AReplacedCard_TakesItsOldContinueCardsWithIt`,
  `R009_Run_DryRun_ListsTheContinueCardUnderItsCard_AndCountsTheKeyOnce`; `FitsHeaderTests`
  for the two methods and `RemoveCards`; `CopyWcsCliTests` the dry run's printed line;
  `LoggingTests` the joined card line. `FitsTestData` gains a `Continue(value)` card.
- **Docs:** `fits-header.md` (the card model), `run-and-console.md` (the outcome's `Cards`),
  `logging.md`, `README.md`, `CHANGELOG.md`, ADR 0022.
