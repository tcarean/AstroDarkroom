## Assumptions (say so at review if one is wrong)

- **CR-006:** a box keeps its text as typed (rewriting it under the cursor would fight the
  typing); only the command line's files show whole in their boxes. The window's three file
  dialogs get `RestoreDirectory`, so nothing in the window moves the working folder.
- **CR-007:** the 1,000 blocks count the block that holds END: END in block 1,000 is read; none
  by then is refused after 2,880,000 bytes. A file of less than 80 bytes keeps today's END
  message (it has no first card); one of 80 bytes or more that is not FITS gets the SIMPLE one.
- **CR-008:** while a file is looked at its fact line is empty and Preview and Copy stay off;
  a look that ends after a newer text was typed is dropped; a run clicked while a look is in
  flight starts when the looks end, so the log's lines between `copy start` and `copy done`
  stay the run's own (R-043). Each look of an existing file writes the reader's `read` line, as
  today's facts do.
- **CR-009:** what clears the card is a change of value of a box (source, destination, new
  file), of the in-place or new-file choice, or of either option; a look again (CR-010) clears
  nothing. A change made during a run does not hide that run's outcome when it ends: a copy's
  lines say a file was written.
- **CR-010:** "before a run" becomes "after every run": the run reads both files itself, and a
  look after it makes the facts agree with what the run found, without the window's `read`
  lines falling inside the run's lines in the log.
- CR-025 (`Copy` enabled with `""`) and the cleanup notes on the dialogs' starting folders stay
  open: other entries.

## Commit 1: CR-006, each path made whole once (R-051, ADR 0023)

- **R-051 (new):** the window makes each path whole once, when it is given: a file from the
  command line against the folder the window started in, and its box shows it whole; a source
  or a destination typed relative against that folder; a new file typed relative against the
  destination's folder. The facts, the run and the core's lines use the whole path. The three
  file dialogs leave the working folder where it was. Example: started in `E:\Night` with
  `solved.fit stack.fit`, the boxes read `E:\Night\solved.fit` and `E:\Night\stack.fit`;
  `out.fit` in the new-file box writes `E:\Night\out.fit` and says `Copied 15 keys into
  E:\Night\out.fit.`; a working folder that moves later changes none of them. R-034 and
  R-032's example point to it.
- **Code:** `App.Parse` keeps `Path.GetFullPath(a)`. `MainViewModel` keeps beside each box's
  text the path made whole when the text is set (`_sourcePath`, `_destPath`; a text
  `GetFullPath` refuses stays as typed, for the core to refuse); the new file is made whole in
  `Request` against the destination's folder (`Path.GetFullPath(text, folder)`). The facts and
  `Request` use those. `MainWindow`'s three dialogs set `RestoreDirectory`; the two factories
  become internal so a test can read it.
- **Tests first** (red today; a test that moves the working folder restores it, and the window's
  test assembly runs one test at a time): `AppTests.R051_TheFilesOfTheCommandLineAreMadeWhole`;
  `MainViewModelTests.R051_ARelativeSourceAndDestinationKeepTheFilesTheyNamedWhenTyped` (the
  working folder moved to a folder holding other files of the same names: the preview and the
  copy are the first folder's, the other files keep every byte);
  `R051_ARelativeNewFileIsWrittenBesideTheDestination` (the file and the line `Copiate 15 chei
  in <dest folder>\out.fit.`); `R051_TheFileDialogsLeaveTheWorkingFolder` (`RestoreDirectory`).
- **Docs:** `window.md`, `README.md` (the window section), `CHANGELOG.md` Fixed, ADR 0023 (the
  measurement; the start folder for the new file rejected).

## Commit 2: CR-007, a file that is not FITS refused at its first card (R-015, ADR 0024)

- **R-015 (amended):** a file whose first card is not `SIMPLE` is refused as that card is read,
  after its first 2,880 bytes at most (`The file does not begin with SIMPLE - it does not look
  like FITS.`); one that ends before an `END` card, or whose header has no `END` in its first
  1,000 blocks of 2,880 bytes, with `Truncated file, or not a valid FITS (the END card is
  missing).` Example: a 10 MB text file is refused after 2,880 bytes, where it was read whole
  and called truncated.
- **Code:** `FitsHeader.ReadFrom` checks the first card once its 80 bytes are in, before the
  short-block check, and stops at `MaxHeaderBlocks = 1000`; the check after the loop goes.
- **Tests first:** `FitsHeaderTests` with a stream that counts what is read:
  `R015_ReadFrom_AFileThatIsNotFits_IsRefusedAtItsFirstCard` (10 MB of text: the SIMPLE
  message, at most 2,880 bytes read; red: all 10 MB read, the END message),
  `R015_ReadFrom_NoEndInTheFirst1000Blocks_IsRefusedThere` (3,000 blocks of key cards: refused
  after 2,880,000 bytes; red), `R015_ReadFrom_AHeaderOf1000Blocks_IsRead` (the boundary, green
  today); `CopyWcsCliTests`: a 10 MB text source gives the SIMPLE line on stderr, exit 1 (red).
- **Docs:** `fits-header.md` (reading), `CHANGELOG.md` Fixed, ADR 0024 (the 5,200 headers).
  The review's case re-run with the Release console on 200 MB of random bytes in the scratchpad:
  time and memory in the outcome.

## Commit 3: CR-008, the facts read off the window's thread (R-052, ADR 0025)

- **R-052 (new):** a box's file is looked at (its existence and its header facts) off the
  window's thread, so a path typed on a slow share never stops the window: while it is looked
  at, its fact line is empty and Preview and Copy are off; when the text changes meanwhile only
  the latest text's look is shown; a Preview or a Copy waits for the looks in flight, then
  runs. Example: a path typed letter by letter on a share that does not answer (2.3 s for one
  letter, measured) leaves the window answering throughout. R-030 points to it.
- **Code (`MainViewModel`):** `LookCore` (`File.Exists` and `Facts`; a test replaces it, as
  `RunCore`); a look per box on `Task.Run`, numbered, its result shown on the caller's thread
  only when its number is still the box's; `FactsRead` (internal), both boxes' latest looks;
  `RunAsync` awaits it before the run; `Copy()`'s destination facts go through a look.
- **Tests first:** `R052_TheWindowStaysLiveWhileAFileIsLookedAt` (a look held in `LookCore`:
  the setter returns at once, the line empty, the commands off until it is released; red: the
  setter waits for the held look), `R052_OnlyTheLatestTextsLookIsShown` (red),
  `R052_ARunWaitsForTheLooksInFlight` (red).
- **Tests changed with the intended change** (each waits for `vm.FactsRead` after a path is
  set, before it reads a fact line or `CanPreview`; no assertion changes): `MainViewModelTests`
  R030 x3, R033 (no `CTYPE1`), R036; `WindowSmokeTests.R034_StartFillsTheBoxesWithTheFilesGiven`
  (made async on the STA thread) and R036's Romanian render;
  `WindowLoggingTests.R043_AFileWhoseFactsCannotBeReadIsADebugLineWithTheException`. Each is
  listed in the outcome.
- **Docs:** `window.md` (the "checked once, in the setters" paragraph), `logging.md` (the facts'
  line comes from a pool thread), `CHANGELOG.md` Fixed, ADR 0025.

## Commit 4: CR-009, the card cleared on a change and during a run (R-053, ADR 0026)

## Commit 5: CR-010, the files looked at again (R-054, ADR 0027)
