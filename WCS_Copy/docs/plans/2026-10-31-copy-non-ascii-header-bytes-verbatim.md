# Copy non-ASCII header bytes verbatim

Plan for the task branch `claude/Copy-non-ASCII-header-bytes-verbatim`, worktree
`.claude/worktrees/Copy-non-ASCII-header-bytes-verbatim` (the project is `WCS_Copy\` inside it).
The owner wrote the decision in full in the request of 2026-10-31, so this file records it as
the approved plan; no plan-mode round was held.

## Context

Since the log task (ADR 0009, merged 2026-10-30 as 2d55c911) `FitsHeader.ReadFrom` decodes each
card with `Encoding.ASCII` and `WriteWithDataFrom` encodes every card with it. A byte above 0x7F
comes out as `?`, in the cards copied and in the destination's own cards the copy never touches,
because the whole header is rewritten; the HISTORY card, built from the source's file name, gets
a `?` for every letter outside ASCII. R-010, `fits-header.md` and the rule "A card is copied
verbatim" in `CLAUDE.md` describe this, and
`R010_Run_AByteAboveAsciiInACopiedCard_IsWrittenAsAQuestionMark` pins it.

Measured by the owner on 2026-10-30: of 3873 FITS files under `E:\Photografie`, no header holds
a byte above 0x7F and no file name holds a letter outside ASCII. The change is one of principle,
not a bug met.

## Decision (the owner's, 2026-10-31)

1. The header is read and written with `Encoding.Latin1`, where every byte 0x00 to 0xFF is one
   character and comes back as the same byte: every card, copied or not, keeps its bytes.
2. The HISTORY card stays ASCII: a letter with a diacritic is transliterated (Unicode
   decomposition FormD, the combining marks dropped: a-breve to `a`, s-comma to `s`, t-comma to
   `t`, i-circumflex to `i`, a-circumflex to `a`, e-acute to `e`, A-ring to `A`), and `?` stands
   only for what has no ASCII form, an emoji for one. The copy never introduces a byte outside
   the standard itself.
3. The log writes a character above 0x7F as `\xNN` (`LogText.Escape`, as for the control
   characters), not as `?`.

A header that is all ASCII comes out byte for byte as before: V-001 and the tests on ASCII files
do not move; the task shows it.

## Steps

1. R-010, R-011 and R-042 in `docs/requirements.md`.
2. The tests, red first: a 0xC5 in a copied card reaches the destination exactly; a 0xC5 in a
   destination card the copy does not touch stays exactly; the HISTORY card of a source with
   `a-breve` in its name writes `a`; the log shows `\xC5`. The R010 question-mark test and
   `R042_ACardIsLoggedAsTheFileHoldsIt_ALetterOutsideAsciiAsAQuestionMark` change with the
   requirements (the latter's HISTORY becomes `Nebula-A.fit`). The test files stay ASCII: a letter
   by its code point, `(char)0x0103`, a byte above 0x7F put into the file's bytes as the R010 test
   of today does.
3. The code: Latin-1 in `FitsHeader`, the transliteration for HISTORY, `\xNN` in
   `LogText.Escape`.
4. ADR 0010 (check before the merge that 0010 is still free on `main`), with the alternatives
   rejected: ASCII as today, the transliteration in HISTORY alone, Latin-1 without the HISTORY
   rule. `fits-header.md`, `logging.md`, the rule in `CLAUDE.md`, CHANGELOG (Changed).
5. The gate, the commit, one subagent review, the merge proposed.

## Verification

`scripts/verify.ps1` green. The Release console's copy of the fixture's solve into a copy of
the fixture, built before the change and after it, gives the same bytes.

## What deviated

- The decomposition is not asked of the runtime. `string.Normalize(FormD)` is a no-op under the
  console's and the core tests' `InvariantGlobalization` (the first run of the new R-011 tests
  gave `???????.fit`; a probe outside and inside invariant mode, pasted in ADR 0010, confirmed
  it), so the console and the window would have written different HISTORY cards for one name.
  The rule is frozen into a table in `AsciiText.cs`, the 495 BMP characters with an ASCII base
  under FormD, generated by a scratch console on .NET 8.0.33, and pinned against the runtime's
  FormD over the whole plane by `AsciiTextTests` in the window's test project, which runs with
  culture data. ADR 0010 records the measurement and rejects the runtime's `Normalize`.
- My first R-010 assertions "no `?` in the file written" read the data area too, where
  `DeterministicData` puts the byte 0x3F by construction; they check the header alone.
- One sentence in `README.md` on the HISTORY card being ASCII, since it is user-visible
  behaviour; the design index row of `fits-header.md` names `AsciiText.cs`.
