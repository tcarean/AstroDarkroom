# Requirements

The source of truth for behaviour. Code follows this file, not the reverse. A behaviour change is
first an edit here (status `draft`), then a test, then code (status `implemented`).

Rules for entries:

- IDs are `R-NNN`, assigned once, never reused. A dropped requirement keeps its ID with status
  `dropped`. Gaps in the numbering are deliberate: each block of ten is one area; a full block
  continues in the next free block of ten, which the area's heading then names.
- Status is one of `draft`, `accepted`, `implemented`, `dropped`. `implemented` means a test named
  `R###_...` exists in a test project under `tests/` (`RepoInvariantTests` checks it both ways).
- Describe observable behaviour, with one concrete example that includes numbers. No adjectives.
- Error behaviour and the exit code are requirements too.

The explanations behind each row (why this way, what was measured) are in `docs/design/` and
`docs/decisions/`; the user documentation of the same behaviour is `README.md`. The rows of
R-001 to R-015 describe the tool as it was built in August 2026 and were written on 2026-10-26

## The console contract (R-001 to R-009)

| ID | Status | Requirement |
| --- | --- | --- |
| R-001 | implemented | Line 1 of every run is `copywcs <version>` and line 2 the copyright line, in every mode, at `--help` and on a failed run; each exactly once. Example: `copywcs 1.0.0` then `Copyright (C) 2026 Tudor Carean`. There is no `--version` flag; it is an unknown option. |
| R-002 | implemented | A usage error (not exactly two paths, an unknown option, `-o` without a value or followed by one that starts with a dash, the file name forgotten) prints one line on stderr saying what is wrong, then the usage on stdout, and exits 2, and nothing is written. Example: one path alone gives `Exactly two files are needed: the source and the destination.`; `copywcs solved.fit stack.fit -o --dry-run` gives `--output needs a file name.` (`--output cere un nume de fisier.`), where it copied into a file named `--dry-run`; a file whose name starts with a dash is given as `.\-x.fit`. |
| R-003 | implemented | `-h` or `--help`, once the parser reaches it (an unknown option before it is still a usage error), prints the usage and the warranty paragraph of GPLv3 section 5(d), which names the LICENSE file and the licence's URL, and exits 0 with nothing on stderr. Every line it writes, the usage's included, here and after a usage error (R-002), ends in the line end of the console's output, CR LF on Windows, as every other line the console writes. Example: `copywcs --help` redirected to a file gives 19 lines, each ending in CR LF, in both languages, where 10 lines of the usage ended in a bare LF. |
| R-004 | implemented | A source or a destination that cannot be read (missing, unreadable, not FITS) gives one line on stderr naming which file and why, exit 1, and nothing is written. Example: `Cannot read the source 'x.fit': Could not find file ...`. |
| R-005 | implemented | When `NAXIS1` or `NAXIS2` differ between the two files, the copy is refused with exit 1 and both sizes named, unless `--force`, which copies and prints a warning line with both sizes first; a file that has no size to compare is R-060's, whatever `--force` says. Example: `Different dimensions: source (100, 80) vs destination (200, 80).` |
| R-006 | implemented | A source without `CTYPE1` gets a warning line on stdout (`WARNING: the source does not look plate-solved (CTYPE1 is missing).`) and the run continues. |
| R-007 | implemented | The keys copied are, in this order and each once: the 32 WCS keys of `WcsMetadataKeys.WcsKeys` (`WCSAXES`, `CTYPE1`, ..., the SIP orders `A_ORDER` to `BP_ORDER` and the SIP convention's largest corrections `A_DMAX` and `B_DMAX`, then `PLTSOLVD`), every `A_i_j`, `B_i_j`, `AP_i_j`, `BP_i_j` card the source has, and, unless `--no-optical`, the 17 optical keys (`FOCALLEN`, `XPIXSZ`, `OBJECT`, `DATE-OBS`, ...); only the keys present in the source. `ABC_1_2` is not a SIP key, and neither is a keyword with anything after its second index: the two indices are the digits 0 to 9, so a keyword field holding `A_1_2` and a line feed, a byte R-010 keeps in a keyword, is neither copied nor dropped (R-016), where it was both and its line feed split the log's line and the drop line. |
| R-008 | implemented | When no key of R-007 is present in the source, one line on stderr (`No relevant key found in the source. Nothing to copy.`), exit 1, nothing written. |
| R-009 | implemented | `--dry-run` prints `Keys that would be copied (N):` and then each card, trimmed and indented by two spaces, one per line, a `CONTINUE` card of R-010 under the card it continues (N counts the keys, not the cards), then the line of R-016 when there is a key to drop, exits 0 and leaves the destination byte for byte as it was. |

## The copy (R-010 to R-019, R-060 to R-069)

| ID | Status | Requirement |
| --- | --- | --- |
| R-010 | implemented | A copied card is the source's 80 bytes, verbatim, formatting and inline comment included; never a reparsed or reformatted value. A card whose value goes on in `CONTINUE` cards, the FITS standard's long string (`OBJECT  = '...&'` then `CONTINUE  '...'`), travels with the `CONTINUE` cards right under it: the copy takes them all, verbatim and in their order, and a card of the destination it replaces, or drops (R-016), goes with the `CONTINUE` cards right under that card. The header is read and written byte for byte (Latin-1, where each byte 0x00 to 0xFF is one character and comes back as the same byte): a byte above 0x7F, which a valid FITS header never holds, is copied as it is, and a card of the destination the copy does not touch keeps it too, though the whole header is rewritten. A header that is all ASCII is written as it was read. Example: a source `OBJECT` card whose comment holds the byte 0xC5 reaches the destination with that byte, and a 0xC5 in the destination's own `COMMENT` card is still there after the copy; a source `OBJECT` of 74 characters, written as `OBJECT  = 'NGC 6960, the Western Veil Nebula, with 52 Cygni in front &'` and `CONTINUE  'of the filaments'`, reaches the destination as those two cards, and a destination whose long `TELESCOP` had a `CONTINUE` card keeps none under the source's `TELESCOP= 'My Scope'`. |
| R-011 | implemented | One `HISTORY WCS copied from <source file name>` card is appended, its text cut at 72 characters; the card is English in both interface languages (ADR 0004) and printable ASCII, the bytes 0x20 to 0x7E a header may hold, whatever the name holds: a letter with a diacritic is written as its base letter (the Unicode decomposition FormD with the combining marks dropped: a with breve U+0103 as `a`, s with comma U+0219 as `s`, t with comma U+021B as `t`, i with circumflex U+00EE as `i`, a with circumflex U+00E2 as `a`, e with acute U+00E9 as `e`, A with ring U+00C5 as `A`), a character with no ASCII form, an emoji for one, as a single `?`, and a control character, below 0x20 or 0x7F, which a Windows file name may hold, as a single `?` too (ADR 0034); the copy itself never puts a byte outside 0x20 to 0x7E in a card it composes. Example: a source named `Nebul` + U+0103 + `.fit` gives `HISTORY WCS copied from Nebula.fit`; one named `Veil` + 0x7F + `1.fit` gives `HISTORY WCS copied from Veil?1.fit`, where the byte 0x7F reached the card. |
| R-012 | implemented | Without `-o` the destination is rewritten in place; with `-o <file>` the new file is written and the destination is left byte for byte as it was. Either way the file is written first under a temporary name beside it, `<name>.copywcs-<8 hex digits>.tmp`, `<name>` shortened when it is too long to take the suffix within the file system's 255 characters, so every name the file system accepts can be written, a name no file holds yet, so a file of the user's such as `<name>.tmp` is never touched, and that file is flushed to the disk and then put in place of its final name at the end, an existing file there replaced so that it keeps its creation time, its attributes (Hidden, for one) and its permissions, as a file of the user's, the old file going for the moment to a backup beside it, `<name>.copywcs-<8 hex digits>.bak`, a name no file holds, deleted once the replace is done: after a success no temporary file and no backup is left, unless another program holds the backup open as it is deleted, which leaves the old file under the backup's name with a Warn line in the log. The target and the data are the files their paths name as the write begins: a working folder that moves while the file is written (a file dialog of the window) changes neither. On success the last two lines are `Copied N keys into <target>.` and the reminder to check the annotation by eye, and the exit code is 0. The count follows each language's grammar, as R-016's line does (ADR 0013): `Copied 1 key into <target>.` for one key; in Romanian `Copiata 1 cheie in <target>.`, `Copiate 15 chei in <target>.`, and from 20 keys on, unless the last two digits are 01 to 19, `Copiate 72 de chei in <target>.` |
| R-013 | implemented | The written file holds the new header, `END`, spaces up to the next 2880-byte boundary, then the destination's data area unchanged; a header that grows past its original number of blocks (for example 41 cards, two blocks) is padded the same way and the data still follows it. |
| R-014 | implemented | A write that fails, before it begins (a target in a folder that does not exist) or midway (a full disk, a drive that drops, a destination whose data cannot be read), gives one line on stderr starting with `Write error:`, which names the file asked for wherever the system's message names a file, never its temporary file (`Write error: Could not find a part of the path 'E:\out\final_wcs.fit'.`), though a rename the system refuses, onto a read-only file, names none (`Write error: Access to the path is denied.`) and, in a folder that lets the user change a file but not create one, the line says access to the file asked for is denied, the temporary file being what cannot be created; exit 1, and leaves the folder as it was, in place and with `-o`: no target file when there was none, an existing target and the destination byte for byte as they were, and no temporary file (R-012), unless the drive that holds it is gone too, when its removal fails as well and the log names it. A replace that Windows leaves half done (its error 1177, reported on some shares and with some security software, never seen on this PC) has moved the old file to its backup: the write puts it back under its own name and the folder is as it was, and the line, whose words from Windows then say the file was renamed, adds `The file was put back as it was.` (`Fisierul a fost pus inapoi cum era.`); when even that fails, nothing more is deleted and the line adds where the file is kept (`Write error: ... The file was kept as 'E:\Night\stack.fit.copywcs-3f9a0c1e.bak'.`, in Romanian `Fisierul a fost pastrat ca '...'.`), the one failed write that leaves files beside the target. Example: an `out.fit` that holds an earlier copy keeps it byte for byte when the next copy into it fails after its first 80 KB of data. |
| R-015 | implemented | A file whose first card is not `SIMPLE` is refused by the reader as soon as that card is read, after the file's first 2,880 bytes at most, with `The file does not begin with SIMPLE - it does not look like FITS.` (`Fisierul nu incepe cu SIMPLE - nu pare FITS.`); a file that ends before an `END` card (shorter than one card, a short file, or exactly 36 cards with no `END`), or whose header has no `END` in its first 1,000 blocks of 2,880 bytes (2,880,000 bytes; the owner's 5,200 FITS files of 2026-11-18 had headers of 1 to 4 blocks), with `Truncated file, or not a valid FITS (the END card is missing).` (`Fisier trunchiat sau nu este FITS valid (cardul END lipseste).`), the reading stopped there. R-004 then reports the message. Example: a 10 MB text file picked by mistake is refused with the first message after its first 2,880 bytes, where it used to be read whole and reported with the second. |
| R-016 | implemented | When the source has `CTYPE1`, the copy first drops from the destination every card whose keyword is one of the 32 WCS keys of R-007 or a SIP coefficient (`A_i_j`, `B_i_j`, `AP_i_j`, `BP_i_j`) and that the source does not have, every card of such a keyword, so that no card of those keys is left in the target but the source's (ADR 0011: Siril 1.4.4 reads a `CD` matrix over `PC` and `CDELT`). Two kinds of card stay as they were, and none of the owner's 231 plate-solved files held either on 2026-11-06: a second card of a keyword the source has (a header should not hold one; R-010's copy replaces the first), and a plate-solve card outside both lists (`RADECSYS`, `PVi_m`, an alternate description such as `CTYPE1A`), which a copy neither takes nor drops. The optical keys are never dropped; no card of those keys is dropped when the source has no `CTYPE1` (R-006), and no card at all when the run is refused, a write that fails included. In place the dropped cards leave the destination; with `-o` they are not carried into the new file, and the destination is left as R-012 says. One line names the keys, in the destination's order, each once, only when there is one to drop: the dry run prints it after the cards (`Old plate-solve keys of the destination that would be dropped (4): CD1_1, CD1_2, CD2_1, CD2_2`), the copy before its last two lines (`Dropped 4 old plate-solve keys of the destination: CD1_1, CD1_2, CD2_1, CD2_2.`, for one key `Dropped 1 old plate-solve key of the destination: RADESYS.`; in Romanian `Eliminata 1 cheie veche ...`, `Eliminate 4 chei vechi ...`, and from 20 keys on, unless the last two digits are 01 to 19, `Eliminate 20 de chei vechi ...`). Example: a destination holding `CD1_1` to `CD2_2`, `CROTA2` and `A_3_0`, and a source holding `CDELT1`, `CDELT2` and `A_0_2` but none of those, gives a target with none of the six. |
| R-017 | implemented | When both files have `CTYPE1`, both `CTYPE1` name the same first axis (`RA` in `'RA---TAN-SIP'`; a solve written `DEC` first, or a `LINEAR` one, is not compared), and both hold a linear part (a `CDi_j` or a `CDELTi` card), the run compares the orientation of their two plate solves, each read as Siril 1.4.4 reads it: the `CD` matrix when the header holds a `CDi_j` card (a missing one 0), else `CDELT1` and `CDELT2` (1 when missing) times the `PC` matrix (the identity where a `PC` card is missing); a `CROTA` turn never mirrors. When the two determinants have opposite signs, the destination's own plate solve is the mirror image of the source's: its pixels were mirrored or flipped after the source was solved, and a copied WCS would point the wrong way (ADR 0012). Without `--force` the run is refused with exit 1 before anything is selected or written, a dry run too: `The destination's own plate solve is a mirror image of the source's: the image was mirrored or flipped after the source was solved, so the copied WCS would be wrong. Flip the image back first, or keep its own plate solve. Use --force if you know what you are doing.`; with `--force` it prints `WARNING: the destination's own plate solve is a mirror image of the source's. Continuing anyway (--force).` and goes on, R-016 included. A value that is not a number, or a determinant of 0, leaves the check out. The check sees a flip only when whatever flipped the pixels flipped the destination's own plate solve with them, as Siril's transforms and the SyQon CLI do; a program that flips the pixels and passes the header through leaves the source's orientation, and the copy goes on as before. A destination whose own plate solve was left mirrored after its pixels were flipped back is refused too: `--force` is for that case. Example: V-002's pair, the Veil stack (`CDELT` and `PC`, determinant -2.96e-6) into its SyQon output (`CD`, determinant +2.96e-6), is refused. |
| R-018 | implemented | A copy writes the target without the destination's `CHECKSUM` card, in place and with `-o`, whatever the source holds: every copy changes the header (the `HISTORY` card of R-011 at least), so the checksum would no longer match it, and the FITS standard's checksum convention asks a program that changes an HDU to update the card or remove it (ADR 0021). `DATASUM` stays as it was, the data area being the destination's, unchanged. Nothing is said on screen; the log has `drop CHECKSUM: <card>` at Debug, a dry run's too, and a dry run or a refused run leaves the destination as it was. Example: V-002's destination, copied with `--force`, comes out without `CHECKSUM= '6jF39j936jE36j93'` and with `DATASUM = '2647693551'`. |
| R-019 | implemented | The source, the destination and a new file (`-o`, the window's `Write a new file`) are three different files, told by the file each path opens and not by its spelling: another letter case, `..`, a `\\?\` prefix, a short 8.3 name or a link that names the same file is that file. After both headers are read, before the dimensions are compared and before anything is selected or written, a dry run included, the run is refused with exit 1 when the source and the destination are one file (`The source and the destination are the same file. Nothing to copy.`), when the new file is the source (`The new file '<path>' is the source itself: writing it would overwrite the plate-solved source. Choose another name for the new file.`), and when the new file is the destination, spelled as the destination is or otherwise (`The new file '<path>' is the destination itself. Write into the destination instead, or choose another name for the new file.`), `<path>` being the new file's path as given; in Romanian `Sursa si destinatia sunt acelasi fisier. Nimic de copiat.`, `Fisierul nou '<path>' este chiar sursa: ...` and `Fisierul nou '<path>' este chiar destinatia. ...`. A new file that does not exist yet is none of them. Example: `copywcs solved.fit Stack.fit -o stack.fit` is refused with the third line, and both files are left byte for byte as they were. |
| R-060 | implemented | A file whose primary header has no image size, `NAXIS1` or `NAXIS2` missing or not a whole number (`NAXIS = 0`, the image in an extension, as astropy and fpack write it), is refused with exit 1, `--force` or not, a dry run too, after the check of R-019 and before the dimensions are compared (R-005): `The source has no image size in its main header (NAXIS1 or NAXIS2 is missing): its image may be in an extension, which this tool does not read.`, or the same line with `The destination has`; the source is checked first, so two such files give the source's line. In Romanian `Sursa nu are dimensiunea imaginii in header-ul principal (lipseste NAXIS1 sau NAXIS2): imaginea poate fi intr-o extensie, pe care unealta nu o citeste.` and `Destinatia nu are ...`. Nothing is written. Example: a source of 100 x 80 and a destination with `NAXIS = 0` are refused with the destination's line, where they were refused as `Different dimensions: source (100, 80) vs destination (-1, -1).` with the advice to force. |
| R-061 | implemented | A card the copy sets takes the place of the destination's card of its keyword, the `CONTINUE` cards under that card going with it (R-010), or, when the destination has none, is appended after the destination's last card, in the order of R-007. `WCSAXES`, which the FITS standard (4.0, section 8.2) puts above every other WCS key, is then moved, when the copy set it, right above the first card of the target whose keyword is a WCS key of R-007 or a SIP coefficient, when such a card stands above it, a destination's own `WCSAXES` the copy replaced too; otherwise no card moves (ADR 0032). Example: a source holding `WCSAXES = 2` (astrometry.net writes it; Siril does not) copied into a destination whose old plate solve begins with `CTYPE1` at card 7 gives a target with `WCSAXES` at card 7 and `CTYPE1` at card 8, where `WCSAXES` came after every card of the destination; astropy 8.0.1 reads both orders the same. |

## The diagnostic log (R-040 to R-049)

| ID | Status | Requirement |
| --- | --- | --- |
| R-040 | implemented | Each application writes a plain-text log, UTF-8 without a BOM, in a folder `log` beside its executable, or in `%LOCALAPPDATA%\CopyWcs\log` when that folder cannot be created, a file cannot be created in it, or the file to be written next cannot be opened for append (the process's first line says which). The file names begin with the executable's name, `copywcs` for the console and `CopyWcs.Wpf` for the window: the first file is `copywcs.log`, and when the file being written passes 1 MiB (1,048,576 bytes) the next is started, `copywcs_01.log`, `copywcs_02.log`, ...; at most 5 files per executable are kept, the oldest deleted first, and the next process goes on in the newest. One executable's rolling never deletes the other's files when both share a folder, and a file another process of the same executable holds open is written beside it. Example: 8 MiB of lines through the console's configuration leave `copywcs_03.log` to `copywcs_07.log`, none above 1 MiB plus one line, the last line in `copywcs_07.log`, where the next run writes too. |
| R-041 | implemented | The log adds nothing to stdout or stderr and never stops a run: a log that cannot be set up leaves the tool working without one. Every line is the local time to 0.1 ms, the level padded to five, `[<process id>:<thread id>]`, the logger's name and the message, with an exception written whole (type, message, stack, inner exceptions) on the lines under it. Each process begins with one line naming the executable and its version, its path, the arguments verbatim, the working folder, the log folder (and the fallback when taken), the level, the OS, the processors, the memory, the .NET runtime, the culture, the time zone and the process id, and ends with `exit <code> after <seconds, one decimal> s`; an exception nobody handled is written at `FATAL` once, even when two hooks see it, and the process ends as it did before. Example: `copywcs 1.0.0 starting; exe=C:\Tools\copywcs.exe; args=["solved.fit", "stack.fit", "--dry-run"]; ...; pid=4312`, then `exit 0 after 0.1 s`. |
| R-042 | implemented | A copy run, from the console or the window, writes: a start line with the request; one line per header read with the file's size, its bytes, cards, blocks, data offset and the bytes after it (`size unknown` and `none` for a stream that cannot tell its length, such as a named pipe, and the run goes on), and `BITPIX`, `NAXIS`, `NAXIS1`, `NAXIS2`, `NAXIS3`, `EXTEND`, `CTYPE1`, `CTYPE2`, `ROWORDER`, `A_ORDER` and `PLTSOLVD` as written (`none` when absent); at Debug the count of keys selected per list, one line per key with the source's card and the destination's card it replaces (`none`, `same`, or that card), a long string's `CONTINUE` cards joined to their card by ` + ` (R-010), one line per card of the destination dropped (R-016) or its `CHECKSUM` (R-018) with that card (`drop CD1_1: CD1_1   = -0.0114`), in a dry run too, and the `HISTORY` card appended; the file written with its size, cards and blocks, and the temporary file it is written through; a line per warning of R-005, R-006 and R-017, the last with both determinants, and at Debug the comparison of R-017 when it passes (`same orientation: source det -9.3025E-8, destination det -9.28E-8`) or cannot be made (`orientation not compared: ... destination det none`); a refusal's reason in English, with the exception that caused it, at `WARN` for a file that cannot be read and at `ERROR` for a write that failed; and a done line with the outcome, the counts (`new`, `replaced`, `identical` and `dropped`, all four always) and the milliseconds of each stage reached (`source`, `dest`, `select`, `write`); a run that throws ends with `copy ended without an outcome after N ms` and its stages.
