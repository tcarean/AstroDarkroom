# Requirements

The source of truth for behaviour. Code follows this file, not the reverse. A behaviour change is
first an edit here (status `draft`), then a test, then code (status `implemented`).

Rules for entries:

- IDs are `R-NNN`, assigned once, never reused. A dropped requirement keeps its ID with status
  `dropped`. Gaps in the numbering are deliberate: each block of ten is one area; a full block
  continues in the next free block of ten, which the area's heading then names.
- Status is one of `draft`, `accepted`, `implemented`, `dropped`. `implemented` means a test named
  `R###_...` exists in a test project under `tests/` (`RepoInvariantTests` checks it both ways).
- Describe observable behaviour, with one concrete example that includes numbers. No adjectives.
- Error behaviour and the exit code are requirements too.

The explanations behind each row (why this way, what was measured) are in `docs/design/` and
`docs/decisions/`; the user documentation of the same behaviour is `README.md`. The rows of
R-001 to R-015 describe the tool as it was built in August 2026 and were written on 2026-10-26
from its tests (ADR 0001); the window rows (R-030 on) are the second task of
`docs/plans/2026-10-26-adopt-the-kit-and-build-the-window.md`, R-038 the plan
`docs/plans/2026-10-28-add-the-top-band-to-the-window.md`, the diagnostic log (R-040 on) the plan
`docs/plans/2026-10-30-add-a-diagnostic-log-with-nlog.md`.

## The console contract (R-001 to R-009)

| ID | Status | Requirement |
| --- | --- | --- |
| R-001 | implemented | Line 1 of every run is `copywcs <version>` and line 2 the copyright line, in every mode, at `--help` and on a failed run; each exactly once. Example: `copywcs 1.0.0` then `Copyright (C) 2026 Tudor Carean`. There is no `--version` flag; it is an unknown option. |
| R-002 | implemented | A usage error (not exactly two paths, an unknown option, `-o` without a value) prints one line on stderr saying what is wrong, then the usage on stdout, and exits 2. Example: one path alone gives `Exactly two files are needed: the source and the destination.` |
| R-003 | implemented | `-h` or `--help`, once the parser reaches it (an unknown option before it is still a usage error), prints the usage and the warranty paragraph of GPLv3 section 5(d), which names the LICENSE file and the licence's URL, and exits 0 with nothing on stderr. |
| R-004 | implemented | A source or a destination that cannot be read (missing, unreadable, not FITS) gives one line on stderr naming which file and why, exit 1, and nothing is written. Example: `Cannot read the source 'x.fit': Could not find file ...`. |
| R-005 | implemented | When `NAXIS1` or `NAXIS2` differ between the two files, the copy is refused with exit 1 and both sizes named, unless `--force`, which copies and prints a warning line with both sizes first. Example: `Different dimensions: source (100, 80) vs destination (200, 80).` |
| R-006 | implemented | A source without `CTYPE1` gets a warning line on stdout (`WARNING: the source does not look plate-solved (CTYPE1 is missing).`) and the run continues. |
| R-007 | implemented | The keys copied are, in this order and each once: the 30 WCS keys of `WcsMetadataKeys.WcsKeys` (`WCSAXES`, `CTYPE1`, ... `PLTSOLVD`), every `A_i_j`, `B_i_j`, `AP_i_j`, `BP_i_j` card the source has, and, unless `--no-optical`, the 17 optical keys (`FOCALLEN`, `XPIXSZ`, `OBJECT`, `DATE-OBS`, ...); only the keys present in the source. `ABC_1_2` is not a SIP key. |
| R-008 | implemented | When no key of R-007 is present in the source, one line on stderr (`No relevant key found in the source. Nothing to copy.`), exit 1, nothing written. |
| R-009 | implemented | `--dry-run` prints `Keys that would be copied (N):` and then each card, trimmed and indented by two spaces, one per line, exits 0 and leaves the destination byte for byte as it was. |

## The copy (R-010 to R-019)

| ID | Status | Requirement |
| --- | --- | --- |
| R-010 | implemented | A copied card is the source's 80 bytes, verbatim, formatting and inline comment included; never a reparsed or reformatted value. The header is read and written as ASCII, as FITS defines it: a byte above 0x7F, which a valid header never holds, is copied as `?`. |
| R-011 | implemented | One `HISTORY WCS copied from <source file name>` card is appended, its text cut at 72 characters; the card is English in both interface languages (ADR 0004). |
| R-012 | implemented | Without `-o` the destination is rewritten in place through a temporary file beside it, which is gone at the end; with `-o <file>` the new file is written and the destination is left byte for byte as it was. On success the last two lines are `Copied N keys into <target>.` and the reminder to check the annotation by eye, and the exit code is 0. |
| R-013 | implemented | The written file holds the new header, `END`, spaces up to the next 2880-byte boundary, then the destination's data area unchanged; a header that grows past its original number of blocks (for example 41 cards, two blocks) is padded the same way and the data still follows it. |
| R-014 | implemented | A write that fails (for example a target in a folder that does not exist) gives one line on stderr starting with `Write error:`, exit 1, and no target file. |
| R-015 | implemented | A file whose first card is not `SIMPLE`, or that ends before an `END` card (a short file, or exactly 36 cards with no `END`), is refused by the reader with one of its two messages, which R-004 then reports. |

## The window (R-030 to R-039)

| ID | Status | Requirement |
| --- | --- | --- |
| R-030 | implemented | The window `CopyWcs.Wpf.exe` takes a plate-solved source, a destination, the choice `Write into the destination` (the default) or `Write a new file` with that file's path, the two options `Copy the optical metadata too` (on) and `Continue even when the dimensions differ` (off), and offers `Preview` and `Copy` beside the options (`About` is in the band at the top, R-038). A path is taken without the whitespace around it. `Preview` and `Copy` are disabled until both paths name existing files, and while a run is in flight (the run goes off the window's thread, so the window stays live during a copy); `Copy` also until the new file's path is not blank when `Write a new file` is chosen. | R-031 | implemented | `Preview` runs the core's dry run and shows, under the core's heading, the cards it selected: trimmed, one per line, in the source's order, exactly the lines `copywcs --dry-run` prints for the same files without their two-space indent, and writes nothing. | R-033 | implemented | A refusal of the core (an unreadable file, different dimensions without force, no relevant key, a write error) is shown under the heading `Refused` with the core's one line, the same line the console writes on stderr, the warnings raised before it above it, no cards and no closing lines, and nothing is written: the destination is byte for byte as it was. ## The diagnostic log (R-040 to R-049)

| ID | Status | Requirement |
| --- | --- | --- |
| R-040 | implemented | Each application writes a plain-text log, UTF-8 without a BOM, in a folder `log` beside its executable, or in `%LOCALAPPDATA%\CopyWcs\log` when that folder cannot be created, a file cannot be created in it, or the file to be written next cannot be opened for append (the process's first line says which). The file names begin with the executable's name, `copywcs` for the console and `CopyWcs.Wpf` for the window: the first file is `copywcs.log`, and when the file being written passes 1 MiB (1,048,576 bytes) the next is started, `copywcs_01.log`, `copywcs_02.log`, ...; at most 5 files per executable are kept, the oldest deleted first, and the next process goes on in the newest. One executable's rolling never deletes the other's files when both share a folder, and a file another process of the same executable holds open is written beside it. Example: 8 MiB of lines through the console's configuration leave `copywcs_03.log` to `copywcs_07.log`, none above 1 MiB plus one line, the last line in `copywcs_07.log`, where the next run writes too. |
| R-041 | implemented | The log adds nothing to stdout or stderr and never stops a run: a log that cannot be set up leaves the tool working without one. Every line is the local time to 0.1 ms, the level padded to five, `[<process id>:<thread id>]`, the logger's name and the message, with an exception written whole (type, message, stack, inner exceptions) on the lines under it. Each process begins with one line naming the executable and its version, its path, the arguments verbatim, the working folder, the log folder (and the fallback when taken), the level, the OS, the processors, the memory, the .NET runtime, the culture, the time zone and the process id, and ends with `exit <code> after <seconds, one decimal> s`; an exception nobody handled is written at `FATAL` once, even when two hooks see it, and the process ends as it did before. Example: `copywcs 1.0.0 starting; exe=C:\Tools\copywcs.exe; args=["solved.fit", "stack.fit", "--dry-run"]; ...; pid=4312`, then `exit 0 after 0.1 s`. |
| R-042 | implemented | A copy run, from the console or the window, writes: a start line with the request; one line per header read with the file's size, its bytes, cards, blocks, data offset and the bytes after it (`size unknown` and `none` for a stream that cannot tell its length, such as a named pipe, and the run goes on), and `BITPIX`, `NAXIS`, `NAXIS1`, `NAXIS2`, `NAXIS3`, `EXTEND`, `CTYPE1`, `CTYPE2`, `ROWORDER`, `A_ORDER` and `PLTSOLVD` as written (`none` when absent); at Debug the count of keys selected per list and one line per key with the source's card and the destination's card it replaces (`none`, `same`, or that card), and the `HISTORY` card appended; the file written with its size, cards and blocks, and for an in-place write the temporary file; a line per warning of R-005 and R-006; a refusal's reason in English, with the exception that caused it, at `WARN` for a file that cannot be read and at `ERROR` for a write that failed; and a done line with the outcome, the counts and the milliseconds of each stage reached (`source`, `dest`, `select`, `write`); a run that throws ends with `copy ended without an outcome after N ms` and its stages. A card is written as the header holds it: without its trailing spaces, a control character as `\xNN`, a character outside ASCII as `?`, which is what the file written holds and what the reader made of such a byte in a file read. Example: the `FitsTestData` pair whose destination has `OBJECT = 'M43'` writes `card OBJECT: OBJECT  = 'M42' \| dest: OBJECT  = 'M43'` and `copy done copied 15 keys into <dest> (new 14, replaced 1, identical 0) in 3 ms (source 0 ms, dest 0 ms, select 0 ms, write 2 ms)`. |
| R-043 | implemented | The applications log their own events: the console a usage error with its line and exit 2, `--help`, and a `--lang` refused with exit 1; the window the language and the two files taken from the command line, a `--lang` it did not understand, the file picked in each dialog, the About window opened, a file whose header facts could not be read (at Debug, with the reader's exception), and a link the About window could not open. A copy from the window writes the same lines as the console's copy of the same request. Example: `CopyWcs.Wpf.exe --lang ro solved.fit stack.fit` writes `language=ro source from the command line: solved.fit dest: stack.fit`. |
| R-044 | implemented | The level is Debug unless the environment variable `COPYWCS_LOG` names another, in any letter case, spaces around ignored: `off`, `fatal`, `error`, `warn`, `info`, `debug` or `trace`; any other value means Debug. Trace adds every card of every header read and of every header written, numbered from 1; `off` creates neither the folder nor a file. Example: with `COPYWCS_LOG=off` a run leaves the folder beside the executable as it was; with `COPYWCS_LOG=trace` the log of a copy holds `card 1: SIMPLE  = T` for the source, the destination and the file written. |
| R-045 | implemented | Two processes of the same executable writing the same file at full speed both keep every line, each whole and once, across the 1 MiB roll too: the log is written through `NLog.Targets.AtomicFile`, which leaves the operating system to place every write at the end of the file (FlatCheck's ADR 0070 measured NLog's plain target losing lines). Example: two writers of 4000 lines each into `CopyWcs.Wpf.log` leave 8000 whole lines in two files, the two writers' lines interleaved. |
| R-046 | implemented | The log's own words are English with invariant numbers whatever `--lang` says and never pass through `T(english, romanian)`: the same run in English and in Romanian writes the same messages, the times aside; an exception's message (under its line) and a usage error's line appear as the user was shown them. Example: under `--lang ro` a copy refused for different dimensions writes `copy done refused: dimensions differ (source 100x80, destination 200x80) in 1 ms (source 0 ms, dest 0 ms, select 0 ms)`. |
