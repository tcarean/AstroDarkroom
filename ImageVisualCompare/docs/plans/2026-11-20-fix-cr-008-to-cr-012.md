## What was measured before the plan (2026-11-20)

- **CR-008 and CR-009: cfitsio's source read** (4.7.0, branch `develop`, `fitscore.c` and
  `getkey.c`; Siril reads FITS through it). `ffpsvc`: a card whose columns 9-10 are not `= ` has
  its value taken from right after the first `=`, so `NAXIS1  =5938` is 5938 in Siril. `ffgphd`:
  a `BSCALE` or `BZERO` that `ffc2dd` cannot convert resets the error and keeps 1.0 or 0.0, so
  Siril shows such a file with the default, as this program does today. `ffc2dd` replaces an
  upper-case `D` only; `3.2768d4` and `32768,0` do not convert.
- **CR-010: no stall.** `result_3813s.fit` (5938 x 3888, three float planes, 277 MB) on the hard
  disk E:, dropped from the Windows cache before each cold run (a handle opened without
  buffering; shown to work: the same read from start to end took 1.53 s cold, 0.22 s warm).
  `FitsImageLoader.Load`, linear: 1.67 s warm, 3.95 and 4.87 s cold; `Histogram`: 2.10 s warm,
  4.33 s cold. The read pattern alone, cold: a row a read (11,664 reads) 3.34 s with
  `RandomAccess`, 3.78 s without; bands of 1 MiB a plane 2.31 s, 4 MiB 1.68 s, 8 MiB 1.64 s; one
  read from start to end 1.48 s. So the entry is severity 4, not 2: a cold FITS costs about 2 to
  3 s more than it has to, and nothing reads as a hang (the drive's own read-ahead hides most of
  the seeks, as the entry allowed). Not measured: a fragmented file, a USB or network disk.
- **CR-011: confirmed.** Recomputed: at a width of 1920, 85 of the heights 600 to 1499 leave an
  overflow of +4.5e-13 image pixels at fit and 85 leave -4.5e-13 (first cases: 601 and 604). Over
  1.9 million random canvases (to 100,000 px) and surfaces (to 8,000 px, whole and fractional)
  the largest residue is 1.3e-12 physical pixels.

## Steps (one commit per entry, requirement and failing test first)

Each step: requirement text in `docs/requirements.md`, the failing test, the fix, the design
note, a line in `CHANGELOG.md`, XML comments on what is added or edited, gate, commit. An
existing test that fails because of a new rule is not edited: stop and report it (the one
expected exception is named in step 5).

### 1. CR-008: a card's value is read from right after `=`

- R-014 gains: a card is a value card when its ninth character is `=`; the value starts right
  after it, with or without the space the standard asks for, as cfitsio reads it.
- Tests in `FitsHeaderTests`: `R014_ReadLayout_ReadsAValueWrittenRightAfterTheEqualsSign`
  (`NAXIS1  =5938`-style cards for `BITPIX` -32, `NAXIS1`, `NAXIS2` and `BZERO`: width 5938,
  bitpix -32, the offset read), and that a quoted string right after `=` is read too. Cards are
  written in the test; `FitsFixture.Card` is not changed.
- Fix: `FitsHeader.ReadCards` passes `card[9..]` to `Value` (which already trims); `Value`'s
  `<param>` says column 10.
- **ADR 0057** "A FITS card's value is read from right after `=`, as cfitsio reads it", with the
  source read and the alternative rejected (refusing the file). `docs/design/imaging.md`.

### 2. CR-009: a `BZERO` or `BSCALE` that is not a number is an invalid header

- R-019's list of the invalid header gains: a `BZERO` or `BSCALE` that does not read as a number
  (`3.2768d4`, `32768,0`, an empty value); the default is taken only when the keyword is absent.
- Test `R019_ABZeroOrBScaleThatDoesNotParse_IsAnInvalidHeader` (theory over both keywords and
  the three values). `R014_ReadLayout_ReadsBZeroAndBScale_AndDefaultsThemToZeroAndOne` (absent
  keyword, `1.0D0`) must stay green untouched.
- Fix: `FitsHeader.Number` returns the fallback only when the keyword is missing, throws
  `InvalidHeader()` when the text does not parse; its `<param>` and summary corrected.
- **ADR 0058** "A `BZERO` or `BSCALE` that is not a number is refused, where cfitsio takes the
  default": the one place the reader is stricter than Siril, and why (a wrong image shown in
  silence). `docs/design/imaging.md`.

### 3. CR-010: each plane is read a band of rows at a time

- No requirement changes (what is shown is the same). The entry's severity is set to 4 in the
  list, with the figures above.
- Before the change: the SHA-256 of the decoded bitmap of both real FITS in the three modes,
  from the throw-away harness in the scratchpad; after it, the same six hashes.
- Tests in `FitsRowDecoderTests`, through a stream that counts its reads:
  `ReadFileRow_ReadsEachPlaneABandOfRowsAtATime_NotARowAtATime` (a three-plane image of 200 rows:
  3 reads, where today there are 600), and `ReadFileRow_GivesTheSameRowsAcrossBandEdges_InAnyOrder`
  (a band of 3 rows on a 10-row image, rows asked forwards, backwards and at the last short band).
- Fix in `src/ImageVisualCompare.Core/FitsRowDecoder.cs`: a buffer per plane holding
  `BandBytes` (4 MiB, by the measurement; at least one row) of consecutive rows; `ReadPlaneRow`
  fills the plane's band when the row asked is outside it and converts from it. The public
  members keep their shape; the band size is an optional constructor parameter so tests can use
  small images. A short read still throws `FitsDataEndsEarly`.
  `FitsImageLoader.OpenRead`: `FileOptions.None` instead of `RandomAccess`, comment and summary
  corrected. Memory: three bands, 12 MiB, while a FITS decodes.
- Re-measure cold and warm with the harness; the figures go into `docs/design/imaging.md` and the
  list. No ADR: the list gave the direction, the note holds the numbers.

### 4. CR-011: a rounding residue at fit is no overflow

- R-043 gains: an overflow of less than a billionth of a physical pixel, which the division at
  fit can leave, is none: no bar. R-041: and no rectangle. Example: 5938 x 3888 on 1920 x 973.
- Tests: `ViewportTests.R043_AtFit_ARoundingResidueIsNoOverflow` (heights 973, 601 and 604 at
  width 1920: `CanScrollVertically` false, `MaxOffsetY` 0, `OffsetY` 0, and `PixelAt(0, 0)` is
  pixel 0, 0 on the fitted axis); the same case in `ScrollBarStateTests` (R-043) and
  `MinimapGeometryTests` (R-041); and one that a real overflow of a hundredth of a pixel still
  scrolls.
- Fix in `src/ImageVisualCompare.Core/Viewport.cs` only: `MaxOffsetX`/`MaxOffsetY` are 0 when
  the overflow times the scale is within `WholeTolerance` (1e-9, about 800 times the largest
  residue measured), and `ClampOffsets` centres such an axis at exactly 0. `ScrollBarStates` and
  `MinimapGeometry` follow through `CanScroll...` unchanged. `docs/design/rendering.md`.
